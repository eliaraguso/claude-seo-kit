## Facts and rules (Google)

### Title links
- The title link is generated **automatically**; Google does not edit it by hand and there is no way to opt out of rewriting. Sources used: `<title>`, the main visual title, `<h1>`/headings, `og:title`, large and prominent text, other text on the page, anchor text on the page and in inbound links, `WebSite` structured data. [G](https://developers.google.com/search/docs/appearance/title-link)
- Every page needs a **descriptive and concise** `<title>`. **There is no character limit**: the title is truncated according to the device width. Practical length heuristic: see [Build rules](#build-rules). [G](https://developers.google.com/search/docs/appearance/title-link)
- Typical causes of rewriting: half-empty titles (`| Brand`), obsolete titles (old year), titles inaccurate for the content, micro-boilerplate (the same title across a group of pages), no clear main title, a language or writing system different from the content, a repeated site name (it can be omitted when already shown as the site name). [G](https://developers.google.com/search/docs/appearance/title-link)
- Avoid: vague titles ("Home", "Profile"), keyword stuffing ("Foobar, foo bar, foo-bar"), text repeated across pages, flight prices. Update the title when the content changes. [G](https://developers.google.com/search/docs/appearance/title-link)
- Brand: on the home page a short description is fine; on other pages put the site name at the start or end, separated by a delimiter (`-`, `:`, `|`). A title may include the business name, physical location and offer details. [G](https://developers.google.com/search/docs/appearance/title-link) [G](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)
- A **clear main title** is needed: one distinct heading (larger font, first visible `<h1>`); several headings with the same visual weight are confusing. [G](https://developers.google.com/search/docs/appearance/title-link)
- Title, H1 and URL **do not need to match**: a natural word overlap is fine. [G OH 2022-12](https://developers.google.com/search/help/office-hours/2022/december) [G OH 2024-06](https://developers.google.com/search/help/office-hours/2024/june)
- A page blocked by robots.txt can still be indexed with a title taken from external sources (e.g. anchors on other sites): to exclude it, use `noindex` with crawling allowed. [G](https://developers.google.com/search/docs/appearance/title-link)
- In paginated sequences, titles and descriptions may be the same (an exception to the distinct-titles rule). Pagination itself: see `crawling-indexing.md`. [G](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading)
- Changes show after a new crawl (days or weeks); a recrawl can be requested with URL Inspection. [G](https://developers.google.com/search/docs/appearance/title-link)

### Meta description, snippets and preview controls
- The snippet is generated automatically, **mainly from the page content**, and changes with the query; the meta description is used when it describes the page better than the content does. No guarantee of use. [G](https://developers.google.com/search/docs/appearance/snippet) [G OH 2023-01](https://developers.google.com/search/help/office-hours/2023/january)
- Google uses it more often when the page has little content or when the description is more relevant to the query than the text. [G OH 2023-09](https://developers.google.com/search/help/office-hours/2023/september)
- Meta description: **no length limit** (truncated by width; heuristic in [Build rules](#build-rules)); **unique per page**; if time is short, prioritise the home page and the most visited pages; it can contain facts (author, date, price, manufacturer, opening hours, location) without prose form; programmatic generation is fine if distinct and readable. Avoid: lists of keywords, the same description everywhere, text that does not summarise the page, text that is too short. [G](https://developers.google.com/search/docs/appearance/snippet)
- Controls: `nosnippet` (no snippet), `max-snippet:[n]` (`0` = same as nosnippet, `-1` = length chosen by Google; ignored if the number cannot be parsed), the `data-nosnippet` attribute (excludes parts of the text). With conflicting rules the **most restrictive** wins. [G](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag)
- `data-nosnippet` is valid only on `span`, `div`, `section`, with well-closed HTML; do not add or remove it with JavaScript on existing nodes (set it when the element enters the DOM). Robots rules do not limit structured data (except `description` of creative works, which `max-snippet` can limit). [G](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag)
- `nosnippet`, `max-snippet`, `data-nosnippet` and `noindex` also apply to **AI Overviews and AI Mode** (they prevent use as direct input). Google-Extended and other AI opt-outs: see the "Controls" table in `ai-search.md`. [G](https://developers.google.com/search/docs/appearance/ai-features) [G](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag)
- Featured snippets cannot be "marked up"; to exclude them use `nosnippet` (reliable) or lower `max-snippet` (no exact threshold). If both `nosnippet` and `data-nosnippet` are present, `nosnippet` prevails. [G](https://developers.google.com/search/docs/appearance/featured-snippets)
- "Read more" deep links to sections: content **immediately visible** (not in closed tabs or accordions), no JS that forces scrolling on load, do not strip the `#` fragment from the URL. [G](https://developers.google.com/search/docs/appearance/snippet)
- `notranslate` (meta or `X-Robots-Tag`) opts the page out of translated results. Google translates results only into a listed set of target languages (checked 2026-10-11: Arabic, Bengali, English, French, German, Gujarati, Hindi, Indonesian, Kannada, Korean, Malayalam, Marathi, Persian, Portuguese, Spanish, Tamil, Telugu, Thai, Turkish, Urdu, Vietnamese). [G](https://developers.google.com/search/docs/appearance/translated-results)

### Head and HTML size
- Only `title`, `meta`, `link`, `script`, `style`, `base`, `noscript`, `template` are valid in `<head>`. An `img` or `iframe` in the head makes Google assume the **head has ended**: metadata after it may be ignored. [G](https://developers.google.com/search/docs/crawling-indexing/valid-page-metadata)
- Googlebot (Search) fetches up to **2 MB per HTML URL** (headers included) and 2 MB per JS/CSS resource; bytes beyond the limit are ignored. PDF: 64 MB. Put title, meta, canonical and essential structured data **near the top**; avoid base64 and bulky inline CSS/JS. [G](https://developers.google.com/search/blog/2026/03/crawler-blog-post)
- Content in `<canvas>`, in plug-ins or generated with the CSS `content` property is not indexed; text inside images does not serve web results. [G](https://developers.google.com/search/docs/fundamentals/get-started-developers) [G OH 2022-12](https://developers.google.com/search/help/office-hours/2022/december)

### Headings
- Use the words people search for in prominent places: title, main heading, alt text, link text. [G](https://developers.google.com/search/docs/essentials)
- **The number and order of headings do not matter for Search** (they matter for screen readers). [G](https://developers.google.com/search/docs/fundamentals/seo-starter-guide) [G OH 2024-07](https://developers.google.com/search/help/office-hours/2024/july)
- Semantic HTML (headings as a summary) can help understanding, but it is not a "secret recipe"; readability for people matters more than perfect code. [G OH 2023-09](https://developers.google.com/search/help/office-hours/2023/september) [G](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)
- Passage ranking evaluates individual sections of a page. *(inference)* Descriptive headings and self-contained sections make passages easier to understand. [G](https://developers.google.com/search/docs/appearance/ranking-systems-guide)
- On mobile use the same clear headings as on desktop. [G](https://developers.google.com/search/docs/crawling-indexing/mobile/mobile-sites-mobile-first-indexing)

### Internal links and anchor text
- Google reliably extracts links only from an `<a href>` that resolves to a real URL. Not recommended: `<span href>`, `<a onclick>` without href, `href="javascript:…"`, routing attributes without `href` in the rendered HTML. Links inserted with JS are fine if the final markup is correct. [G](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)
- Googlebot **does not click buttons**; URLs in `<select><option>` are not links. [G OH 2023-09](https://developers.google.com/search/help/office-hours/2023/september) [G OH 2023-05](https://developers.google.com/search/help/office-hours/2023/may)
- Anchor text: descriptive, reasonably concise, relevant. Avoid: "click here", "learn more", empty links, very long anchors, links next to each other without context, forced keywords. For image links the anchor is the `alt`; if `<a>` is empty Google may use `title`. [G](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)
- Every important page needs a link from at least one other page of the site; **there is no ideal number** of links. [G](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)
- Google infers relative importance from depth (clicks needed) and the number of inbound internal links, not from the folder structure. [G](https://developers.google.com/search/docs/specialty/ecommerce/help-google-understand-your-ecommerce-site-structure)
- Near-identical internal anchors (menus, cards) are normal. [G OH 2022-11](https://developers.google.com/search/help/office-hours/2022/november)
- Infinite scroll / "load more": each chunk with a unique, stable URL (e.g. `?page=12`) and sequential links; Google neither scrolls nor clicks. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/lazy-loading)

### URLs
- **Do not use `#` fragments** to change content (e.g. `/#/potatoes`): Search generally does not support them; use the History API. [G](https://developers.google.com/search/docs/crawling-indexing/url-structure)
- Parameters as `key=value` separated by `&`; as few as possible; no session IDs or temporary values in internal links. [G](https://developers.google.com/search/docs/crawling-indexing/url-structure) [G](https://developers.google.com/search/docs/specialty/ecommerce/designing-a-url-structure-for-ecommerce-sites)
- Descriptive words in the audience's language, percent-encoding where needed, **hyphens** (not underscores) between words; URLs are **case-sensitive**. [G](https://developers.google.com/search/docs/crawling-indexing/url-structure)
- Keywords in the domain or path: **almost no** ranking effect (mainly useful as breadcrumbs). Do not change URLs for SEO "tricks". [G](https://developers.google.com/search/docs/fundamentals/seo-starter-guide) [G OH 2023-05](https://developers.google.com/search/help/office-hours/2023/may)

### Images
- Use `<img src>` (also inside `<picture>`, always with a fallback `src`). **CSS images (`background-image`) are not indexed.** [G](https://developers.google.com/search/docs/appearance/google-images)
- Formats in `img src`: **BMP, GIF, JPEG, PNG, WebP, SVG, AVIF** (AVIF since 2024); extension consistent with the type; Google detects the format from the `Content-Type` header. Data URIs are allowed but add weight. [G](https://developers.google.com/search/docs/appearance/google-images) [G](https://developers.google.com/search/blog/2024/08/happy-avifriday) [G OH 2023-03](https://developers.google.com/search/help/office-hours/2023/march)
- `alt` is the **most important** attribute: descriptive, in context, without stuffing (spam risk). Inline SVG: `<title>` with `aria-labelledby`. Images near relevant text, useful captions, **descriptive file names**, the same URL for the same image. [G](https://developers.google.com/search/docs/appearance/google-images)
- Preferred image (thumbnail in Search and Discover, still chosen automatically): `primaryImageOfPage` on `WebPage`, or `image` of the main entity (`mainEntity`/`mainEntityOfPage`), or `og:image`. Avoid logos, generic images or images with a lot of text, extreme aspect ratios; use high resolution. [G](https://developers.google.com/search/docs/appearance/google-images)
- `max-image-preview`: `none`, `standard`, `large` (up to the viewport width). Case study: +79% and +30% CTR with `large`. [G](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag) [G](https://developers.google.com/search/case-studies/large-images-case-study)
- Image sitemaps: up to **1,000** `<image:image>` per `<url>`; `<image:loc>` can be on another domain (verify both in Search Console); `caption`, `title`, `geo_location`, `license` are retired. [G](https://developers.google.com/search/docs/crawling-indexing/sitemaps/image-sitemaps)
- Lazy loading: load when the element enters the viewport (native or IntersectionObserver), never tied to scroll or click events; **do not apply it to content visible immediately**. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/lazy-loading)
- EXIF is not used; the metadata used is IPTC. If images change URL, redirect from the old URLs (images are crawled less often). [G OH 2023-01](https://developers.google.com/search/help/office-hours/2023/january) [G OH 2023-12](https://developers.google.com/search/help/office-hours/2023/december)

### Video
- Embed with `<video>`, `<embed>`, `<iframe>` or `<object>`, present in the rendered HTML **without user actions** (scroll, click, typing); never load the video through `#`. [G](https://developers.google.com/search/docs/appearance/video)
- Video results, key moments and the LIVE badge need a **dedicated watch page** (the video is the main purpose, shown prominently). The page must be indexed and rank well; thumbnail at a stable URL. [G](https://developers.google.com/search/docs/appearance/video) [G OH 2023-12](https://developers.google.com/search/help/office-hours/2023/december)
- Thumbnail: BMP, GIF, JPEG, PNG, WebP, SVG, AVIF; **minimum 60x30 px** (larger preferred); accessible to Googlebot and Googlebot-Image; with transparency, at least 80% of pixels with alpha > 250; the same URL in all sources. [G](https://developers.google.com/search/docs/appearance/video)
- `VideoObject` with a unique `name`, `description`, `thumbnailUrl` per video; video sitemap; `max-video-preview` (`0` = static image only, `-1` = no limit); data URLs not supported; an `expires` in the past excludes the video. Key moments: `Clip` (all languages where Search is available) or `SeekToAction` (a listed subset of languages; check the page); opt out with `nosnippet`. [G](https://developers.google.com/search/docs/appearance/video)
- A YouTube video plus the same text on the page is not duplicate content. [G OH 2024-08](https://developers.google.com/search/help/office-hours/2024/august)

### Favicon
- `<link rel="icon" href="…">` (also `shortcut icon`, `apple-touch-icon`, `apple-touch-icon-precomposed`) **in the head of the home page**; relative or absolute `href`, CDN allowed. [G](https://developers.google.com/search/docs/appearance/favicon-in-search)
- **One favicon per hostname** (domain or subdomain, not subdirectory). Googlebot-Image must be able to crawl the file and Googlebot the home page. [G](https://developers.google.com/search/docs/appearance/favicon-in-search)
- **Square 1:1, minimum 8x8 px, recommended larger than 48x48 px.** Supported formats: BMP, GIF, ICO, PNG, JPEG, PPM, TIFF. SVG is not listed on the English page (last updated 2026-08-28, checked 2026-10-11): browsers may use an SVG icon, but give Search a listed format as well. It must represent the brand; stable URL. Updates take days or weeks. [G](https://developers.google.com/search/docs/appearance/favicon-in-search)
- Changing the favicon: update every declared file, redirect from the old file to the new one, wait (up to about a month). [G OH 2023-05](https://developers.google.com/search/help/office-hours/2023/may) [G OH 2024-07](https://developers.google.com/search/help/office-hours/2024/july)

### Site name
- Generated **automatically** from the home page and references on the web. The strongest signal: **`WebSite` structured data on the home page**; then `og:site_name`, `<title>`, headings and text of the home page. [G](https://developers.google.com/search/docs/appearance/site-names)
- **One name per site**, defined by domain or subdomain (`www` and `m` count as the domain); **subdirectories are not supported**. `WebSite` goes only on the home page (root URI), in a single node (nest other properties there). [G](https://developers.google.com/search/docs/appearance/site-names)
- Required properties `name` and `url` (canonical home page); recommended `alternateName` (an array in order of preference is allowed). Formats: JSON-LD, RDFa, microdata. [G](https://developers.google.com/search/docs/appearance/site-names)
- Name concise, unique, commonly recognised, **not generic** ("Best Dentists in Iowa" does not work); used consistently across the home page; no character limit but it may be truncated. [G](https://developers.google.com/search/docs/appearance/site-names)
- Duplicate home pages (HTTP/HTTPS, www/non-www): **the same structured data on all of them**; the name reflects the redirect target. If the name is not picked up: check consistency, then add `alternateName`, then the **lowercase domain** as the last `alternateName`, and as a last resort as `name`. [G](https://developers.google.com/search/docs/appearance/site-names)
- Test with validator.schema.org: the **Rich Results Test does not support site names**. [G](https://developers.google.com/search/docs/appearance/site-names)

### Sitelinks
- Fully automatic, derived from the **link structure**; shown only when useful, never guaranteed. What helps: informative and compact titles and headings, internal links to the important pages, concise anchors, no repetition. To remove one: `noindex` or delete the page. [G](https://developers.google.com/search/docs/appearance/sitelinks)
- The **sitelinks search box was removed on 21 November 2024**: `SearchAction` markup is useless but harmless; **do not remove** the `WebSite` block used for the site name. [G](https://developers.google.com/search/blog/2024/10/sitelinks-search-box)

### Breadcrumbs and visible URL
- Result attribution = favicon + site name + visible URL (domain + breadcrumb). [G](https://developers.google.com/search/docs/appearance/visual-elements-gallery)
- **Since 23 January 2025 mobile results show only the domain**; breadcrumbs remain on desktop. `BreadcrumbList` (a list of `ListItem` with `position`, `name`, `item`; multiple trails allowed) is still supported. [G](https://developers.google.com/search/blog/2025/01/simplifying-breadcrumbs) [G](https://developers.google.com/search/docs/appearance/structured-data/breadcrumb)

### Discover
- Eligibility is automatic if the content is **indexed** and meets the Discover policies; no special tag or structured data; eligibility ≠ being shown. [G](https://developers.google.com/search/docs/appearance/google-discover)
- Images: **width ≥ 1200 px**, **> 300,000 total pixels**, **16:9** aspect ratio, enabled by `max-image-preview:large` (or AMP); point to a large, representative image via schema.org or `og:image`, not the logo, not one with a lot of text. [G](https://developers.google.com/search/docs/appearance/google-discover)
- No clickbait, misleading or exaggerated details in title/snippet/image, no sensationalism; titles that capture the essence; an overall good page experience. Discover may not show job applications, petitions, forms, **code repositories**, satire without context. Discover report: 16 months, above an impressions threshold. [G](https://developers.google.com/search/docs/appearance/google-discover)
- A Discover-only core update (February 2026) brought more local content per country, less clickbait and more expertise **per topic**. [G](https://developers.google.com/search/blog/2026/02/discover-core-update)

### Core Web Vitals and page experience
- Core Web Vitals (LCP, INP, CLS), field vs lab data, their weight in ranking and the causes and fixes by rendering mode now live in `performance-cwv.md` (checks PF-01 to PF-22). This file keeps the other page experience aspects: interstitials, mobile and HTTPS (below). [G](https://developers.google.com/search/docs/appearance/page-experience)

### Interstitials and ads
- Prefer **banners that take up a small part of the screen** (also for app installs and newsletters). Avoid full-page overlays and redirects to a separate page for consent or input. [G](https://developers.google.com/search/docs/appearance/avoid-intrusive-interstitials)
- Mandatory interstitials (e.g. age verification) are allowed, preferably overlaid on the content and **without an HTTP redirect**; for adult content let verified Googlebot access the page without the check. [G](https://developers.google.com/search/docs/appearance/avoid-intrusive-interstitials)
- Ads on mobile: follow the Better Ads Standards; the main content must remain distinguishable. [G](https://developers.google.com/search/docs/crawling-indexing/mobile/mobile-sites-mobile-first-indexing)

### Mobile
- **Mobile-first** indexing with Googlebot smartphone. Mobile and desktop must have **the same main content, headings, title and meta description, robots meta, structured data, alt text and image quality**; do not load the main content only after an interaction; make videos easy to find. [G](https://developers.google.com/search/docs/crawling-indexing/mobile/mobile-sites-mobile-first-indexing)
- Separate mobile URLs complicate everything: prefer responsive design. With m-dot sites the desktop URL is the canonical. [G OH 2024-04](https://developers.google.com/search/help/office-hours/2024/april) [G OH 2023-01](https://developers.google.com/search/help/office-hours/2023/january)

### HTTPS
- Serve the site over HTTPS (a self-assessment question; HTTPS report in Search Console). HTTP sites may be flagged as not secure in Chrome. [G](https://developers.google.com/search/docs/appearance/page-experience) [G](https://developers.google.com/search/docs/fundamentals/get-started)
- An HTTPS page must not load HTTP resources (mixed content): some browsers refuse to load or run them and the page breaks. Redirect HTTP to HTTPS and then enable HSTS, but only once HTTPS is stable (HSTS is a security measure, not a ranking factor). Search Central's former HTTPS page now redirects to this web.dev article. [G](https://web.dev/articles/enable-https)
- Moving from HTTP to HTTPS needs a new Search Console property (or a Domain property). HSTS has no effect on ranking. [G OH 2024-04](https://developers.google.com/search/help/office-hours/2024/april) [G OH 2023-06](https://developers.google.com/search/help/office-hours/2023/june)

### Publication dates
- Google estimates the date from several factors; showing it is not guaranteed. Provide a **visible date** with a label ("Published", "Last updated") and/or `datePublished`/`dateModified` in a `CreativeWork` type (`Article`, `BlogPosting`, `VideoObject`…). [G](https://developers.google.com/search/docs/appearance/publication-dates)
- Date required, time optional (recommended with time zone, ISO 8601); **consistency** between the visible date and structured data; **no future dates** and not the date of the event described; reduce other dates on the page. [G](https://developers.google.com/search/docs/appearance/publication-dates)
- Changing the date without substantial changes is a sign of search-engine-first content. `lastmod` in the sitemap only for significant changes. [G](https://developers.google.com/search/docs/fundamentals/creating-helpful-content) [G OH 2023-01](https://developers.google.com/search/help/office-hours/2023/january)

### AI features (appearance)
- **No additional requirements or markup** for AI Overviews and AI Mode. Requirement: the page is **indexed and eligible to show a snippet**. Opt-outs and Search Console controls for generative AI features: see the "Controls" table in `ai-search.md`. Important content **as text**, structured data consistent with the visible text. [G](https://developers.google.com/search/docs/appearance/ai-features) [G](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)
- `llms.txt`, files or Markdown "for AI", chunking: **not used** by Search (neither positive nor negative). [G](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)
- Measurement: AI traffic is included in the "Web" search type of the Performance report; the generative AI performance report (impressions, no clicks) became available to all properties on 31 August 2026; a "multimodal" filter was added on 24 September 2026. [G](https://developers.google.com/search/blog/2026/06/gen-ai-performance-reports) [G](https://developers.google.com/search/blog/2026/09/web-multimodal-in-sc)

### Paywalled content (only if relevant)
- A paywall is not cloaking if Google sees all the protected content and the flexible sampling guidelines are followed. Mark it with `isAccessibleForFree: false` and `hasPart` with `cssSelector` (`.class` selectors only). [G](https://developers.google.com/search/docs/essentials/spam-policies) [G](https://developers.google.com/search/docs/appearance/structured-data/paywalled-content)
- A monthly quota is preferable to a daily one; for news 6–10 articles per user per month, suggested starting point 10; satisfaction drops if the paywall appears more than 10% of the time. [G](https://developers.google.com/search/docs/appearance/flexible-sampling)

### Other appearance elements
- Rich result types Google retired in 2025 (Book actions, Course info, ClaimReview, Estimated salary, Learning video, SpecialAnnouncement, Vehicle listing; no ranking impact): see the "Retired or restricted rich results" table in `structured-data.md`. [G](https://developers.google.com/search/blog/2025/06/simplifying-search-results) [G](https://developers.google.com/search/blog/2025/11/update-on-our-efforts)
- Preferred sources (mostly news): domains/subdomains only; JS button or deep link `google.com/preferences/source?q=domain`. [G](https://developers.google.com/search/docs/appearance/preferred-sources)

## Build rules
- **Page template**: a unique, descriptive `<title>` (`Topic – Brand`), a unique meta description, one visible main title consistent with the title, page-specific `og:title`/`og:description`/`og:image`, `max-image-preview:large`. → OP-01, OP-02, OP-03, OP-06, OP-07, OP-08, OP-22, OP-23 [G](https://developers.google.com/search/docs/appearance/title-link)
- **Title and description length**: Google sets no character limit; truncation depends on pixel width and device. Practical heuristic: about 50-60 characters for titles and 120-160 for descriptions; never pad or cut meaning to hit a number; one unique, descriptive title and description per page. → OP-02, OP-03, OP-08 [G](https://developers.google.com/search/docs/appearance/title-link) [G](https://developers.google.com/search/docs/appearance/snippet)
- **Clean head, near the top**: title, meta, canonical, hreflang and essential JSON-LD at the start of the HTML; no `img`/`iframe` in the head; HTML well under 2 MB. → OP-11, OP-12 [G](https://developers.google.com/search/docs/crawling-indexing/valid-page-metadata) [G](https://developers.google.com/search/blog/2026/03/crawler-blog-post)
- **JavaScript sites/SPAs**: title, meta, canonical and main content present in the served or rendered HTML for every route (SSR/prerendering lowers the risk); verify with URL Inspection. *(inference)* from Google's documents on rendering and byte limits. → OP-01, OP-40 [G](https://developers.google.com/search/docs/fundamentals/get-started-developers)
- **One URL per piece of content**, without `#`, with words in the audience's language and hyphens; navigation with `<a href>`. → OP-17, OP-18, OP-14 [G](https://developers.google.com/search/docs/crawling-indexing/url-structure)
- **Decide the site name early**: identical in `WebSite.name`, `og:site_name`, title and heading of the home page; `alternateName` with the short form/acronym and the lowercase domain as a fallback; site on its own domain or subdomain. → OP-29 [G](https://developers.google.com/search/docs/appearance/site-names)
- **Brand favicon**, square (larger than 48x48; e.g. a large PNG + ICO), in the head of the home page, at a URL without a hash that changes at every build. → OP-28 [G](https://developers.google.com/search/docs/appearance/favicon-in-search)
- **Images**: `<img>`/`<picture>` with `src`, `alt`, `width`/`height`; WebP/AVIF allowed; descriptive file names; no lazy loading on the main image; no important text inside images. → OP-19, OP-20, OP-21, OP-24, OP-40 [G](https://developers.google.com/search/docs/appearance/google-images)
- **Video**: embedded directly; a dedicated page if the video is the main content; `VideoObject` + video sitemap. → OP-26, OP-27 [G](https://developers.google.com/search/docs/appearance/video)
- **Internal links**: menu, footer and contextual links to the important pages; anchors that make sense on their own, out of context. → OP-15, OP-16 [G](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)
- **Write for people**: the words readers use in the title, main heading, alt text and links; heading order and number are free; clear sections. → OP-06, OP-20 [G](https://developers.google.com/search/docs/essentials)
- **Meta description** as a factual summary (what the page offers + useful data: location, opening hours, price, author, date); no keyword lists. → OP-08 [G](https://developers.google.com/search/docs/appearance/snippet)
- **Articles**: visible date + `datePublished`/`dateModified`; change the date only with substantial edits. → OP-39 [G](https://developers.google.com/search/docs/appearance/publication-dates)
- **Performance**: a budget that meets LCP < 2.5 s, INP < 200 ms, CLS < 0.1; critical JS and CSS on the same host; measure with real-user data after launch. → OP-33, OP-34 [G](https://developers.google.com/search/docs/appearance/core-web-vitals)
- **HTTPS from day one**, 301 redirects from http and from the non-preferred www/non-www variant; every resource over HTTPS. → OP-35, OP-30, OP-46 [G](https://developers.google.com/search/docs/fundamentals/get-started)
- **Pop-ups**: newsletter, consent and promotions as banners or partial dialogs, never full-page overlays or redirects to consent pages. → OP-37 [G](https://developers.google.com/search/docs/appearance/avoid-intrusive-interstitials)
- **Responsive**, with the same content on mobile and desktop. → OP-36 [G](https://developers.google.com/search/docs/crawling-indexing/mobile/mobile-sites-mobile-first-indexing)
- **No markup "for AI"**: for AI Overviews/AI Mode, indexing, snippet eligibility, clear text and consistent structured data are enough. → OP-40, OP-45 [G](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)
- **Preview controls** only as deliberate choices: `data-nosnippet` for parts to exclude (e.g. cookie notices, legal text), knowing it applies to AI features too. → OP-09, OP-10 [G](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag)

## Notes by site type
**ecommerce** (example: Acme Widgets, acme-widgets.example)
- Product titles: product name plus the attribute that tells it apart (brand, model, size or colour where it matters), then the site name with a delimiter, e.g. `Blue Steel Widget 40 mm – Acme Widgets`; a title may include offer details. Avoid one identical title for a whole group of variants or categories (micro-boilerplate). → OP-02, OP-03 [G](https://developers.google.com/search/docs/appearance/title-link)
- Product descriptions: unique per product; programmatic generation from product facts (price, manufacturer, key specs) is fine if each one is distinct and readable. → OP-08 [G](https://developers.google.com/search/docs/appearance/snippet)
- Variants: each variant has its own URL, as a path (`/t-shirt/green`) or a `key=value` parameter (`/t-shirt?color=green`), never `?green` alone and never a `#` fragment (`/t-shirt#black` and `/t-shirt#white` are the same page for Google). When variants use optional query parameters, the canonical URL omits the parameter. Product variant markup helps Google group variations of the same parent product. → OP-17, OP-18 [G](https://developers.google.com/search/docs/specialty/ecommerce/designing-a-url-structure-for-ecommerce-sites) [G](https://developers.google.com/search/docs/appearance/structured-data/product-variants)
- Product images: in `<img>` (not CSS backgrounds), high resolution, crawlable and indexable URLs, a format supported by Google Images; pictures that clearly show the product (e.g. on a white background) are preferred for merchant listings; several images, at least 50,000 pixels (width × height), in 16:9, 4:3 and 1:1. Set the product image as `image` of the `Product` main entity. → OP-19, OP-21, OP-22 [G](https://developers.google.com/search/docs/appearance/structured-data/merchant-listing) [G](https://developers.google.com/search/docs/appearance/google-images)
- Categories and linking: menu → categories → subcategories → products with `<a href>`; link every product you want indexed; best sellers from the home page; a search box is not a substitute for links (Googlebot does not submit searches). → OP-14, OP-16 [G](https://developers.google.com/search/docs/specialty/ecommerce/help-google-understand-your-ecommerce-site-structure)
- Category pagination: `<a href>` links and unique URLs; each page has its own canonical (the first page is not the canonical of all of them); pages in a sequence may share title and description. Pagination, sort/filter parameters and crawl budget: see `crawling-indexing.md`. → OP-41 [G](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading)
- Product data: Google recommends both `Product` structured data on product pages and a Merchant Center feed; syntax in `structured-data.md`. → OP-45 [G](https://developers.google.com/search/docs/specialty/ecommerce/share-your-product-data-with-google)

**editorial**
- Visible date, consistent with structured data; large images (≥ 1200 px) and `max-image-preview:large` for Discover; faithful titles, not clickbait. → OP-39, OP-22, OP-23, OP-43 [G](https://developers.google.com/search/docs/appearance/google-discover)
- Visible author with a link to the author page (details in `content-quality-spam.md`). Meta description with author/date where useful. [G](https://developers.google.com/search/docs/appearance/snippet)
- Paywalled or members-only content: paywalled-content structured data. → OP-42 [G](https://developers.google.com/search/docs/appearance/structured-data/paywalled-content)

**local-business** (example: Northwind Physio, northwind-physio.example)
- Home page meta description on Google's model: what it offers + opening hours + where it is (e.g. "Sports physiotherapy and rehab in central Oslo. Open Mon–Sat 8–20, near Oslo S."). City/area in the title where relevant. → OP-08 [G](https://developers.google.com/search/docs/appearance/snippet) [G OH 2023-03](https://developers.google.com/search/help/office-hours/2023/march)
- Address, phone, opening hours and services as HTML text (not only images, PDFs or JS widgets). → OP-40 [G](https://developers.google.com/search/docs/fundamentals/get-started-developers)
- Booking or newsletter pop-ups as banners, not interstitials. Keep the Google Business Profile up to date (also cited for AI features). → OP-37 [G](https://developers.google.com/search/docs/appearance/ai-features)

**personal-brand** (example: Ada Novak, adanovak.example)
- Site name = first and last name or personal brand (a generic role such as "Full Stack Developer" would not be chosen); `alternateName` with variants. → OP-29 [G](https://developers.google.com/search/docs/appearance/site-names)
- Title with name + role/expertise; avoid "Home", "Profile", "Projects" on their own (negative examples cited by Google). → OP-03 [G](https://developers.google.com/search/docs/appearance/title-link)
- One page per project with text, `<img>` images with alt, and an embedded demo video if any: more distinct pages = more queries covered and possible sitelinks. *(inference)* Discover may not recommend code repositories: for a developer like Ada Novak, project pages on adanovak.example work better than links to a code host alone. [G](https://developers.google.com/search/docs/appearance/google-discover)

**professional-services** (example: Studio Ferri Orientamento, studioferri.example)
- Same rules as local-business when the practice serves a place (title and description with the service and the city where relevant); otherwise the title names the service and the professional, and the description summarises who it is for and how to get in touch. → OP-03, OP-08 [G](https://developers.google.com/search/docs/appearance/title-link) [G](https://developers.google.com/search/docs/appearance/snippet)
- Contact details, services and credentials as HTML text, not only in PDFs or images. → OP-40 [G](https://developers.google.com/search/docs/fundamentals/get-started-developers)

## Third-party views
- [SEJ 2026-03, news, Google confirmation to The Verge] Google tested AI-rewritten titles in search results in a "small and narrow" way; cited analyses estimate "traditional" rewrites on 61–76% of titles. Consistent with Google (automatic titles); the percentages are third-party.
- [SEJ 2025-10, Clarkson-Bennett, opinion based on the "Google leak"] ⚠ "Max 12 words / 600 pixels" rules for titles: these are not Google limits (no character limit, truncation by width).
- [SEJ 2026-06, Mueller on Reddit] The meta description is not a requirement but is worth writing on important pages; no penalty. Consistent with Google.
- [SEJ 2026-06, Montti, opinion] ⚠ A ~120-character, factual description without a CTA or forced keywords: the "factual and unique" part is in line with Google; the length is the author's choice.
- [SEJ 2026-02, Mueller, real case] A default HTTP home page left live next to the HTTPS one caused a wrong site name and favicon: Chrome upgrades to HTTPS, Googlebot does not. Verify with curl.
- [SEJ 2026-02, Bill Hunt, enterprise case] `WebSite` placed on every location page made one location show as the site name: keep `WebSite` on the home page only (consistent with Google).
- [SEJ 2026-03, Mueller] For legacy names after a rebrand, the domain name usually works as an alternate name (consistent with the documentation).
- [SEJ 2026-03, news on Google docs] Three ways to indicate the preferred image (`primaryImageOfPage`, `image` on mainEntity, `og:image`): consistent with Google.
- [SEJ 2026-07, web.dev Nuvemshop case flagged by Mueller] LCP improved by removing CSS transitions at the top, removing `loading="lazy"` from the first image and using `fetchpriority="high"` on 1–2 images; first check which element is the real LCP element. Self-reported data.
- [SEJ 2025-12 and 2026-05, HTTP Archive/CrUX] Share of sites with good Core Web Vitals per platform (e.g. April 2026: Duda ~85%, Wix ~80%, Shopify ~79%, WordPress ~49%); page weight and Lighthouse score do not predict real Core Web Vitals. Descriptive data, not causal.
- [SEJ 2025-12, news] Safari 26.2 exposes LCP and INP via RUM; CrUX, PSI and Search Console remain Chrome-based: Safari users need your own measurement.
- [SEJ 2025-11, Mueller] A heavy hero video loaded in the background after the content should have no visible SEO effect.
- [SEJ 2026-05, news on Google docs] FAQ rich results stopped showing on 7 May 2026 (reported by SEJ 2026-05; re-verify on the Google changelog): `FAQPage` markup is harmless but useless for Google. ⚠ Against advice that calls it "critical for GEO". Retired and restricted rich results: see `structured-data.md`.
- [SEJ 2026-09, Mueller] In the Search Console AI report, the links in an AI Overview inherit the block's position: "position" there is of little use; measure outcomes instead.
- [SEJ 2025–2026, various authors] ⚠ "Citable structure" (answer in 2–3 sentences, short paragraphs, H2s as questions) to get cited by AI: a hypothesis from correlations on ChatGPT, not Google guidance. Google: no special optimisation, chunking not needed.
- [SEJ 2025-10, news, Bing] Bing also supports `data-nosnippet` for snippets and Copilot answers.

## Myths and outdated advice
- **"A title over N characters/pixels is penalised"**: myth. Google sets no limit; it truncates according to the device. Length heuristic: [Build rules](#build-rules). [G](https://developers.google.com/search/docs/appearance/title-link)
- **"A meta description over N characters (e.g. 150–160) is penalised"**: myth; there is no limit. [G](https://developers.google.com/search/docs/appearance/snippet)
- **Meta keywords**: not used by Google. [G](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)
- **"One H1 and headings in perfect order for ranking"**: number and order do not matter for Search (they matter for accessibility). [G](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)
- **"Title = H1 = URL"**: not needed. [G OH 2024-06](https://developers.google.com/search/help/office-hours/2024/june)
- **Keywords in the domain/URL as a ranking lever**: almost no effect; Google does not give much credit to domains created to match a query. [G](https://developers.google.com/search/docs/fundamentals/seo-starter-guide) [G](https://developers.google.com/search/docs/appearance/ranking-systems-guide)
- **Sitelinks search box (`SearchAction`)**: removed on 21 November 2024. [G](https://developers.google.com/search/blog/2024/10/sitelinks-search-box)
- **Breadcrumbs shown in mobile results**: since 23 January 2025 mobile shows the domain only. [G](https://developers.google.com/search/blog/2025/01/simplifying-breadcrumbs)
- **Rich results for Course info, Fact check, Estimated salary, Learning video, SpecialAnnouncement, Book actions, Vehicle listing**: retired in 2025; see the "Retired or restricted rich results" table in `structured-data.md`. [G](https://developers.google.com/search/blog/2025/06/simplifying-search-results)
- **"Site name only for the domain, not for subdomains"** (OH May 2023): superseded; subdomains are supported today. [G](https://developers.google.com/search/docs/appearance/site-names)
- **"INP is not part of the Core Web Vitals"** (OH September 2023): superseded; the current documentation lists LCP, INP, CLS (FID no longer appears). [G](https://developers.google.com/search/docs/appearance/core-web-vitals)
- **"Lighthouse/PSI score = ranking"**: real-user data is what counts; a perfect score is not an SEO goal. [G](https://developers.google.com/search/docs/appearance/page-experience) [G OH 2024-06](https://developers.google.com/search/help/office-hours/2024/june)
- **`rel="next"`/`rel="prev"`**: no longer used by Google. [G](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading)
- **Cached copy as an indicator**: the cache link was removed in 2024 and was never a quality signal. [G OH 2024-04](https://developers.google.com/search/help/office-hours/2024/april)
- **Image EXIF as a signal**: not used. [G OH 2023-01](https://developers.google.com/search/help/office-hours/2023/january)
- **W3C validation, ARIA, `<article>`, HSTS, HTTP/3 as ranking factors**: no direct effect (a valid head does matter, for reading metadata). [G OH 2023-08](https://developers.google.com/search/help/office-hours/2023/august) [G OH 2023-06](https://developers.google.com/search/help/office-hours/2023/june) [G](https://developers.google.com/search/docs/crawling-indexing/valid-page-metadata)
- **`llms.txt`, Markdown for bots, schema "for AI", chunking**: ignored by Google Search. [G](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)
- **Moving critical JS/CSS to a separate subdomain/CDN "for crawl budget"**: advised against since 6 December 2024, for performance reasons. [G](https://developers.google.com/search/blog/2024/12/crawling-december-resources)
- **"Text inside images is enough, Google does OCR"**: web results need HTML text (alt, captions, body text). [G OH 2022-12](https://developers.google.com/search/help/office-hours/2022/december)
