## Facts and rules (Google)

### Crawling vs indexing
- The right tool for each goal: **do not crawl → robots.txt**; **do not index → `noindex`**; **keep out users and crawlers → password/authentication**. [G](https://developers.google.com/search/docs/crawling-indexing/googlebot)
- Minimum requirements: Googlebot not blocked, page returns **HTTP 200**, indexable content. 4xx and 5xx pages are not indexed. Meeting the requirements **does not guarantee** indexing. [G](https://developers.google.com/search/docs/essentials/technical)
- A URL blocked by robots.txt **can still appear** in results (without a snippet) if it is linked; to keep it out you need `noindex` **with crawling allowed**. [G](https://developers.google.com/search/docs/crawling-indexing/robots/intro) · [G](https://developers.google.com/search/docs/crawling-indexing/block-indexing)
- Discovery happens mostly through links (also sitemaps, redirects, RSS feeds); keeping a site secret is almost impossible. [G](https://developers.google.com/search/docs/crawling-indexing/googlebot) · [G OH 2024-07](https://developers.google.com/search/help/office-hours/2024/july)
- Recrawl frequency ranges from a few minutes (home pages of news sites) to about a month for stable pages; on average Googlebot accesses a site no more than once every few seconds. [G](https://developers.google.com/crawling/docs/about-crawling) · [G](https://developers.google.com/search/docs/crawling-indexing/googlebot)
- Crawling is required to appear but **is not a ranking factor**; more crawling does not mean better rankings. [G](https://developers.google.com/crawling/docs/myths-about-crawling)
- Google does not index everything: many "not indexed" URLs are normal and the report does not need to reach zero. "Index bloat" is not a Google concept. [G OH 2024-07](https://developers.google.com/search/help/office-hours/2024/july) · [G OH 2023-06](https://developers.google.com/search/help/office-hours/2023/june)

### robots.txt
- **Location**: root of the host (`https://www.example.com/robots.txt`); it applies only to the **protocol + host + port** where it is served (not to `m.`, `http://`, `:8181`, nor `www` ↔ apex); a file in a subfolder is not valid; IDNs in punycode. [G](https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec)
- **Format**: UTF-8 text, CR/LF/CRLF line endings; BOM and invalid lines are ignored; if Google receives HTML it tries to extract rules from it. **500 KiB limit**: content beyond it is ignored. [G](https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec)
- **Supported fields**: only `user-agent`, `allow`, `disallow`, `sitemap`. **Not supported** (ignored): `crawl-delay`, `clean-param`, `noindex` and others. Field names are case-insensitive; **paths are case-sensitive** and must start with `/`; rules without a path are ignored. [G](https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec) · [G](https://developers.google.com/search/blog/2025/03/robots-future)
- **Groups**: a crawler follows **only one group**, the one with the most specific user-agent; order in the file is irrelevant; groups for the same user-agent are merged; **a specific group and `*` are not combined** (e.g. if `User-agent: Googlebot` exists, Googlebot ignores the `*` rules). Consecutive `user-agent` lines share the rules; a `sitemap` line does not end the group. [G](https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec)
- **Matching**: `*` (0+ characters) and `$` (end of URL); the rule with the **longest path** wins; on a tie the least restrictive (`allow`) wins. `/fish` matches `/fish.html` and `/fishheads` but not `/Fish.asp` or `/catfish`; `/*.php$` does not match `.php?x=`; `allow: /$` + `disallow: /` = home page only. [G](https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec)
- **HTTP status of the file**: `2xx` processed; `3xx` followed for at least 5 hops, then treated as `404` (JS redirects and meta refresh are not followed); **`4xx` (except `429`) = no restrictions**; **`5xx`**: crawling of the site is suspended for 12 hours, then for up to 30 days Google uses the last valid cached copy (no copy: no restrictions), after 30 days no restrictions if the site is available; network/DNS errors = server error. Do not use `401`/`403` to limit crawl rate. [G](https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec)
- **Caching**: usually up to **24 hours** (longer if the file is unreachable), shared between crawlers, influenced by `Cache-Control: max-age`; fast refresh with "Request a recrawl" in the Search Console robots.txt report. [G](https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec) · [G](https://developers.google.com/crawling/docs/robots-txt/submit-updated-robots-txt)
- `sitemap:` takes an absolute URL (protocol + host), may point to another host, unlimited number, not tied to a user-agent; Google does not infer http/https/www variants. [G](https://developers.google.com/crawling/docs/robots-txt/create-robots-txt)
- `AdsBot-Google`, `AdsBot-Google-Mobile`, `Mediapartners-Google`, `APIs-Google` **ignore `*`**: they must be named explicitly to be blocked. [G](https://developers.google.com/crawling/docs/crawlers-fetchers/google-special-case-crawlers)
- robots.txt is **not** for private content (the file is public and blocked URLs can be indexed), nor for canonicalization, nor for removals; it manages load and useless URL spaces. Do not block resources needed to understand the page. [G](https://developers.google.com/search/docs/crawling-indexing/robots/intro) · [G](https://developers.google.com/crawling/docs/robots-txt/useful-robots-txt-rules)
- Testing: Search Console robots.txt report; open-source library `github.com/google/robotstxt`; on managed hosting (Wix, Blogger) use the platform settings. [G](https://developers.google.com/crawling/docs/robots-txt/create-robots-txt)
- Google's official example for blocking an AI training crawler while letting search engines through: `user-agent: *` + `allow: /`; `user-agent: <training-bot>` + `disallow: /` (+ `allow: /$` for the home page only). [G](https://developers.google.com/search/blog/2025/03/robotstxt-flexible-way-to-control)

### Meta robots and X-Robots-Tag
- Rules are read **only if the crawler can access the URL**: a `noindex` on a URL blocked by robots.txt is never seen. `noindex` **in robots.txt is not supported**. [G](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag) · [G](https://developers.google.com/search/docs/crawling-indexing/block-indexing)
- Meta names: `robots` (all crawlers), `googlebot`, `googlebot-news`; others are ignored. Non-search crawlers (e.g. AdsBot) need their own meta. Values are case-insensitive. [G](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag)
- `X-Robots-Tag` (HTTP header) supports every rule, also for PDFs/images/videos; the user-agent is optional (`X-Robots-Tag: googlebot: nofollow`). [G](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag)
- Conflicts: the **most restrictive** rule wins; rules for different crawlers add up (`robots: nofollow` + `googlebot: noindex` → noindex, nofollow for Googlebot). [G](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag)
- Valid rules: `all`, `noindex`, `nofollow`, `none`, `nosnippet`, `indexifembedded` (only with `noindex`), `max-snippet:[n]` (`0` = nosnippet, `-1` = no limit), `max-image-preview:[none|standard|large]`, `max-video-preview:[n]`, `notranslate`, `noimageindex`, `unavailable_after:[date]` (RFC 822/850, ISO 8601). [G](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag)
- `nosnippet` and `max-snippet` also apply to **AI Overviews and AI Mode** (they limit use of the content as direct input). Other AI controls (Search Console AI setting, `Google-Extended`): see `ai-search.md` › Controls: what blocks what. [G](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag)
- Obsolete/ignored: `noarchive`, `nocache`, `nositelinkssearchbox`, `noodp`. Default is `index, follow`: no need to declare it; the absence of a robots meta/header **is not a problem**. [G](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag) · [G OH 2024-08](https://developers.google.com/search/help/office-hours/2024/august)
- Placement: the documentation says to place the tag in the `<head>` and that Google also respects robots meta tags in the `<body>`; in February 2026 Illyes and Splitt said only the `<head>` counts (see Third-party views). Operational rule: **always in the head**. [G](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag)
- After adding `noindex` the page must be recrawled (this can take months for minor pages). Many `noindex` pages or internal `nofollow` links are not a low-quality signal. [G](https://developers.google.com/search/docs/crawling-indexing/block-indexing) · [G OH 2024-08](https://developers.google.com/search/help/office-hours/2024/august)
- `X-Robots-Tag: noindex` on sitemap files keeps them out of the index if they show up in results. [G OH 2023-12](https://developers.google.com/search/help/office-hours/2023/december)

### Sitemaps
- Formats: XML (most versatile), RSS 2.0/mRSS/Atom 1.0, text (`.txt`, one URL per line). [G](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)
- Limits per file: **50,000 URLs or 50 MB uncompressed**; a sitemap index holds up to **50,000 `loc`**; up to **500 index files** per site in Search Console. Compression is allowed but does not increase crawl budget. [G](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap) · [G](https://developers.google.com/search/docs/crawling-indexing/sitemaps/large-sitemaps) · [G](https://developers.google.com/crawling/docs/myths-about-crawling)
- UTF-8, **absolute**, fully qualified URLs, crawled exactly as written; only **canonical** URLs you want in results; order does not matter. Without submission through Search Console a sitemap covers only descendants of its own directory → put it at the root. [G](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)
- `<lastmod>` is used **if it is consistently and verifiably accurate**, for the last significant change (main content, structured data, links; not the copyright year). **`<priority>` and `<changefreq>` are ignored.** [G](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)
- Useful for large sites, **new sites with few external links**, sites with lots of media or news; it may not be needed below about **500 pages** with good internal linking. It is not mandatory; the file name is free. [G](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview) · [G OH 2024-04](https://developers.google.com/search/help/office-hours/2024/april)
- Submission: Sitemaps report, Search Console API, `Sitemap:` line in robots.txt, WebSub (RSS/Atom). It is a hint: it **does not guarantee** crawling or indexing. [G](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)
- Do not resubmit the same unchanged sitemap several times a day; Google reprocesses only changed sitemaps (URLs or `lastmod`); removing a URL from the sitemap does not remove it from the index. [G](https://developers.google.com/search/docs/crawling-indexing/troubleshoot-crawling-errors) · [G OH 2023-06](https://developers.google.com/search/help/office-hours/2023/june)
- Cross-site sitemaps: all sites verified in Search Console, or a declaration in each site's robots.txt. [G](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)
- Extensions: images max **1,000 `<image:image>` per `<url>`**; `image:caption`, `image:title`, `image:license`, `image:geo_location` retired. Video `description` ≤ 2,048 characters, `duration` 1–28,800 s, max 32 `tag`; `category`, `gallery_loc`, `price`, `tvshow` retired. News: only articles from the last 2 days, max 1,000 `<news:news>`. [G](https://developers.google.com/search/docs/crawling-indexing/sitemaps/image-sitemaps) · [G](https://developers.google.com/search/docs/crawling-indexing/sitemaps/video-sitemaps) · [G](https://developers.google.com/search/docs/crawling-indexing/sitemaps/news-sitemap)
- An HTML sitemap does not replace the XML one; it often signals navigation that needs improving. [G OH 2023-06](https://developers.google.com/search/help/office-hours/2023/june)

### Canonicalization and duplicates
- Google groups identical or very similar pages and picks the most representative as canonical (crawled more often). Some duplication is normal and **does not violate spam policies**; there is no "duplicate content penalty". [G](https://developers.google.com/search/docs/crawling-indexing/canonicalization) · [G](https://developers.google.com/search/help/crawling-index-faq)
- Signals by strength: **redirect** (strong), **`rel="canonical"`** (strong), **sitemap** (weak); combining them reinforces them. Others: HTTPS preferred over HTTP, URLs in reciprocal `hreflang` clusters, internal and external links. The declared canonical is a **hint**. [G](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls) · [G OH 2022-11](https://developers.google.com/search/help/office-hours/2022/november)
- Best practice: **self-referencing** canonical on canonical pages; **absolute URL**; in a valid `<head>`; **one method only** (HTML element or `Link` header, useful for PDFs); internal links always to the canonical; with hreflang, canonical in the same language. [G](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)
- Do not: use robots.txt or the Removals tool to canonicalize; declare different canonicals with different techniques; use `#` fragments as canonicals; use `noindex` to choose the canonical within a site; combine `rel="canonical"` with `hreflang`/`lang`/`media`/`type` (ignored; use `rel="alternate"`). [G](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)
- HTTPS is reinforced by HTTP→HTTPS redirects, canonicals to HTTPS, HSTS; avoid invalid certificates, HTTPS→HTTP redirects, HTTP URLs in sitemaps/hreflang, certificates not matching the host. HSTS has no ranking effect. [G](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls) · [G OH 2023-06](https://developers.google.com/search/help/office-hours/2023/june)
- Diagnosis: URL Inspection shows the canonical chosen by Google; after differentiating grouped pages, re-evaluation can take **up to 2 weeks**. Common causes: regional variants without hreflang, wrong canonicals/redirects from the CMS or plugins, a server serving the same content on several hosts, identical soft 404s, hacking. [G](https://developers.google.com/search/docs/crawling-indexing/canonicalization-troubleshooting)
- Syndication: cross-domain canonical is discouraged; better if partners use `noindex`. [G](https://developers.google.com/search/docs/crawling-indexing/canonicalization-troubleshooting) · [G OH 2023-06](https://developers.google.com/search/help/office-hours/2023/june)
- A self-referencing canonical on its own "does nothing", but it helps when the page is reached with parameters (UTM). Canonicalization decides which URL is shown, not ranking. [G OH 2022-11](https://developers.google.com/search/help/office-hours/2022/november) · [G OH 2024-08](https://developers.google.com/search/help/office-hours/2024/august)

### Redirects
- Permanent (target = canonical): server-side `301`, `308` (preferred), `meta refresh` at 0 s / `Refresh: 0` header, JS `location` (only if server-side is impossible), "we have moved" link (last resort). Temporary: `302`, `303`, `307`, refresh > 0 s. **`308` = `301`** for Google. [G](https://developers.google.com/search/docs/crawling-indexing/301-redirects) · [G OH 2023-04](https://developers.google.com/search/help/office-hours/2023/april)
- Googlebot follows **up to 10 hops**; in migrations point straight to the final target, ideally **≤ 3 and < 5 hops**. `Google-InspectionTool` does not follow redirects. [G](https://developers.google.com/crawling/docs/troubleshooting/http-status-codes) · [G](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes)
- Permanent redirects **do not lose PageRank**; there is no limit on the number of `301`s; long-lasting temporary redirects are treated as permanent; the same rules apply to PDFs, images, videos. [G](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes) · [G OH 2022-12](https://developers.google.com/search/help/office-hours/2022/december) · [G OH 2023-05](https://developers.google.com/search/help/office-hours/2023/may) · [G OH 2023-07](https://developers.google.com/search/help/office-hours/2023/july)
- Redirect only to an **equivalent replacement**; many URLs redirected to the home page or to categories may be treated as **soft 404**; "when in doubt, don't redirect" (serve 404). [G](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes) · [G OH 2024-08](https://developers.google.com/search/help/office-hours/2024/august)
- Meta refresh: not supported by every browser; a server-side `301` is better. [G](https://developers.google.com/search/docs/crawling-indexing/special-tags)

### HTTP status codes, network and DNS
- `200`: goes to indexing (not guaranteed); if it looks like an error → **soft 404**. `201`/`202`: limited wait. `204`: nothing to index. [G](https://developers.google.com/crawling/docs/troubleshooting/http-status-codes)
- `304`: content unchanged, no effect on indexing. [G](https://developers.google.com/crawling/docs/troubleshooting/http-status-codes)
- `4xx` (400, 401, 403, 404, 410…): content ignored, URLs removed from the index, crawling gradually reduced; **all treated the same except `429`**; do not use `401`/`403` to limit crawling. `4xx` responses do not waste crawl budget (except `429`). [G](https://developers.google.com/crawling/docs/troubleshooting/http-status-codes) · [G](https://developers.google.com/crawling/docs/myths-about-crawling)
- `404`s are normal and **do not harm** the rest of the site; they matter only when an important page becomes a 404. [G OH 2023-07](https://developers.google.com/search/help/office-hours/2023/july) · [G OH 2024-08](https://developers.google.com/search/help/office-hours/2024/august)
- `5xx` and `429`: crawling slows down proportionally; indexed URLs are kept, then **removed if the error persists**. Emergencies: `500`/`503`/`429` for a few hours or **1–2 days at most**; beyond ~2 days URLs may drop out of the index. Short, occasional `503`s (deploys) are not a problem. [G](https://developers.google.com/crawling/docs/crawlers-fetchers/reduce-crawl-rate) · [G](https://developers.google.com/search/docs/crawling-indexing/troubleshoot-crawling-errors) · [G OH 2024-04](https://developers.google.com/search/help/office-hours/2024/april)
- Timeouts, connection resets and **DNS errors = `5xx`**: indexed URLs that cannot be reached drop out of the index **within a few days**. DNS: firewall allowing UDP and TCP queries, correct `A`/`CNAME` records on **all** name servers, propagation up to 72 hours. [G](https://developers.google.com/crawling/docs/troubleshooting/dns-network-errors)
- Returning different codes to Googlebot and to users (e.g. `410` to the bot, `200` to users) is **status-code cloaking**. [G OH 2023-04](https://developers.google.com/search/help/office-hours/2023/april)
- The file type is determined by the **`Content-Type`** header (then the extension). [G](https://developers.google.com/search/docs/crawling-indexing/indexable-file-types)

### URL structure, parameters and facets
- URLs conform to IETF STD 66 with reserved characters encoded; **no fragments** to change content; parameters as `key=value` separated by `&`. [G](https://developers.google.com/search/docs/crawling-indexing/url-structure)
- Readability: descriptive words in the audience's language, not long IDs; **hyphens** (not underscores); as few parameters as possible; URLs are **case-sensitive** (normalize if the server does not distinguish); no session IDs; root-relative links, not `../`. Keywords in the URL: minimal effect. [G](https://developers.google.com/search/docs/crawling-indexing/url-structure) · [G OH 2024-04](https://developers.google.com/search/help/office-hours/2024/april)
- Infinite spaces (calendars, combinable filters, internal search, sort orders): robots.txt or `nofollow` on links to future pages. For internal search see [Internal search result pages](#internal-search-result-pages). [G](https://developers.google.com/search/docs/crawling-indexing/url-structure)
- **Faceted navigation** (the leading cause of over-crawling): if it is not needed in Search → robots.txt (e.g. `disallow: /*?*products=`) or `#` fragments; if it is needed → standard `&`, constant filter order, `404` for empty combinations (no redirect to a shared 404, except in SPAs). Canonicals and `nofollow` (on **all** links) are less effective in the long run. [G](https://developers.google.com/crawling/docs/faceted-navigation)
- Ecommerce: no internal links with temporary parameters; same URL in links, sitemap and canonical; self-referencing canonical; every paginated page canonical to itself (not to the first page, see [Pagination](#pagination)). [G](https://developers.google.com/search/docs/specialty/ecommerce/designing-a-url-structure-for-ecommerce-sites) · [G](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading)

### Internal search result pages
Internal search result pages (`/search?q=`, `?s=`) are an infinite URL space: Google's URL structure page suggests blocking "dynamic URLs, such as URLs that generate search results" with robots.txt. This file owns the decision; other files point here. One decision tree, never two rules at once:
1. **Never indexed** (new site, or none appear in the Page indexing report or a `site:` query): block crawling with `Disallow` in robots.txt (e.g. `Disallow: /search` or `Disallow: /*?s=`). No `noindex` is needed: it would not be read.
2. **Already indexed**: first serve `noindex` (meta or `X-Robots-Tag`) **with crawling allowed**; wait until the pages have dropped out of the index (Page indexing report "Excluded by 'noindex' tag", `site:` query); only then add `Disallow` if crawl load justifies it.
3. **Never both at once**: a `Disallow` hides the `noindex`, so the URLs can stay indexed (→ CI-09, CI-34).

[G](https://developers.google.com/search/docs/crawling-indexing/url-structure) · [G](https://developers.google.com/crawling/docs/robots-txt/useful-robots-txt-rules) · [G](https://developers.google.com/search/docs/crawling-indexing/block-indexing)

### Pagination
- Paginated pages of blogs, categories and listings (`/page/2`, `?page=2`) stay **crawlable**: each has its own URL and a **self-referencing canonical**; do not use page 1 as the canonical of the series; link each page to the next with `<a href>` (Google does not click buttons or trigger JavaScript that needs user action); no `#` fragments for page numbers. [G](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading)
- Do **not** put paginated archives in robots.txt `Disallow` and do not `nofollow` the pagination links: they are how Google reaches older posts and products. Infinite scroll / "load more" needs the same paginated URLs behind it (→ RJ-22, OP-41). `rel="next"`/`rel="prev"` are no longer used. [G](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading) · [G](https://developers.google.com/search/docs/crawling-indexing/special-tags)
- Filter and sort variations of a listing are a different case: they may be kept out with `noindex` or robots.txt as described under faceted navigation. [G](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading)

### Mobile-first
- Google indexes and ranks the **mobile version** (Googlebot Smartphone). **Responsive design** is recommended; dynamic serving and separate URLs (m-dot) require `Vary: User-Agent` and more care. [G](https://developers.google.com/search/docs/crawling-indexing/mobile/mobile-sites-mobile-first-indexing)
- Mobile/desktop parity: same robots meta (a `noindex` on mobile blocks the page), content, headings, title, description, structured data, images with the same `alt` and stable URLs, videos; do not block mobile resources; no main content loaded only on interaction. [G](https://developers.google.com/search/docs/crawling-indexing/mobile/mobile-sites-mobile-first-indexing)
- m-dot: desktop page canonical (`rel="alternate" media="only screen and (max-width: 640px)"`), mobile page with `rel="canonical"` to desktop; same status codes; a mobile equivalent for every page; separate hreflang; no fragments. Googlebot Smartphone and Desktop share the `Googlebot` token. [G](https://developers.google.com/search/docs/crawling-indexing/mobile/mobile-sites-mobile-first-indexing) · [G](https://developers.google.com/search/docs/crawling-indexing/googlebot)
- `<meta name="viewport">` signals a mobile-optimized page. [G](https://developers.google.com/search/docs/crawling-indexing/special-tags)

### International and hreflang
- **Distinct URLs per language/country** (ccTLD, subdomain, subdirectory; parameters discouraged); not cookies, `Accept-Language` or IP. Googlebot crawls mostly from US IPs and **does not send `Accept-Language`**. [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites) · [G](https://developers.google.com/search/docs/specialty/international/locale-adaptive-pages)
- **Do not redirect automatically** by language or IP; offer links to switch language; one language per page (content and navigation). [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites) · [G OH 2024-08](https://developers.google.com/search/help/office-hours/2024/august)
- Language is detected from the content: **Google uses neither `hreflang` nor the `lang` attribute** to detect it; it ignores geo meta tags. [G](https://developers.google.com/search/docs/specialty/international/localized-versions) · [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)
- hreflang: three equivalent methods (`<link>` in the head, `Link` header, sitemap with `xhtml:link`, which does not count toward the URL limit); each version lists **itself and all others**; **return links are mandatory** (otherwise ignored); **absolute** URLs with protocol; `x-default` for selectors/redirects; ISO 639-1 codes (+ ISO 3166-1 Alpha 2): **not** `es-419`, `EU`, `UN`, **`UK`** (use `GB`), not a country alone (`be` = Belarusian); do not combine with `media`. `noindex` URLs do not join the cluster. [G](https://developers.google.com/search/docs/specialty/international/localized-versions) · [G OH 2023-01](https://developers.google.com/search/help/office-hours/2023/january)
- Translated versions **are not duplicates** (they are only if the main content is not translated); same language for several countries → canonical + hreflang. [G](https://developers.google.com/search/docs/specialty/international/localized-versions) · [G](https://developers.google.com/search/docs/crawling-indexing/canonicalization)
- TLDs: a ccTLD is a country signal; `.io`, `.me`, `.co`, `.tv` etc. are treated as generic, `.eu`/`.asia` as generic; `.ai` has been a gTLD since 2023. [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites) · [G OH 2023-07](https://developers.google.com/search/help/office-hours/2023/july)

### Site moves and hosting changes
- With URL changes (HTTP→HTTPS, domain, paths): old→new mapping, **server-side `301`/`308`**, one change at a time, canonicals/hreflang/internal links updated, new sitemap, development `noindex`/`Disallow` removed (no robots.txt = a correct `404`). Keep redirects **at least 1 year**. Timing: a few weeks for small/medium sites. [G](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes)
- The Search Console **Change of Address** tool is **only** for domain/subdomain changes (not HTTP→HTTPS, www↔non-www, paths), and must be submitted for **every verified variant** of the old domain (subdomains, www/non-www), even unused ones. [G](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes)
- Hosting/CDN change without URL changes: test environment with `noindex`, check firewalls/DoS protection that might block Googlebot, **lower the DNS TTL at least one week before**, keep verification; crawling drops temporarily, then recovers. [G](https://developers.google.com/search/docs/crawling-indexing/site-move-no-url-changes)
- HTTP→HTTPS needs a new Search Console property or a **Domain** property (covers all variants). [G OH 2024-04](https://developers.google.com/search/help/office-hours/2024/april)

### Crawl budget and HTTP caching
- Google's crawl budget guide is written for: sites with **more than 1 million unique pages** whose content changes about once a week, sites with **more than 10,000 unique pages** whose content changes daily, and sites with a large share of URLs in "Discovered – currently not indexed". Google calls these figures rough estimates. This file owns these thresholds; other files point here. The budget is **per hostname**. [G](https://developers.google.com/crawling/docs/crawl-budget)
- Budget = capacity (connections, delay, "host load"; rises with fast responses, falls with `5xx`/`429`) + demand (size, freshness, quality, relevance); **capacity is shared among all Google crawlers**. [G](https://developers.google.com/crawling/docs/crawl-budget)
- Practices: reduce duplicates and useless URLs, robots.txt for useless spaces, `404`/`410` for removed pages, no soft 404s, sitemap with `lastmod`, no redirect chains, fast pages, `304`. **`noindex` does not save budget**; robots.txt does not "reassign" budget unless the site is at its capacity limit. [G](https://developers.google.com/crawling/docs/crawl-budget)
- HTTP caching (RFC 9111): `ETag`/`If-None-Match` (preferred) and `Last-Modified`/`If-Modified-Since` (format `Fri, 4 Sep 1998 19:15:56 GMT`), ideally both; **`304` response without a body**; `Cache-Control: max-age` recommended; other directives not supported. [G](https://developers.google.com/crawling/docs/crawlers-fetchers/overview-google-crawlers) · [G](https://developers.google.com/search/blog/2024/12/crawling-december-caching)
- Protocols: HTTP/1.1 and HTTP/2 (no ranking advantage; `421` to opt out); gzip, deflate, Brotli compression. [G](https://developers.google.com/crawling/docs/crawlers-fetchers/overview-google-crawlers)

### Recrawling and timing
- A few URLs: **URL Inspection → Request indexing** (quota; repeating it does not speed things up; needs full access to the property). Many URLs: **sitemap**. Timing ranges from a few days to a few weeks; no guarantee. [G](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl)
- For most sites it takes several days to discover new pages and at least ~3 days to see updates; do not expect same-day indexing (except news). [G](https://developers.google.com/search/docs/crawling-indexing/troubleshoot-crawling-errors)
- The most common reason for non-indexing: **the site is too new**; others: few links, structure, blocks, unavailability, quality. [G](https://developers.google.com/search/help/crawling-index-faq)
- The **Indexing API** applies only to job postings and livestreams. [G OH 2024-04](https://developers.google.com/search/help/office-hours/2024/april)

### Temporary closure
- Recommended: keep the site online with limited functions (cart disabled, banner with `data-nosnippet`, updated structured data). Switch it off only for a few days: **`503` for 1–2 days** (with `Retry-After`), a `200` placeholder home page for longer periods. **Never** use a `503` robots.txt, `Disallow: /`, `403`/`404`/`410`, `noindex` or the Removals tool for a closure. Do not block the US. [G](https://developers.google.com/search/docs/crawling-indexing/pause-online-business)

### Removals and private content
- Permanent removal: delete the content (`404`/`410`), password-protect it, or `noindex`; **not** robots.txt. Removals tool: temporary, about **6 months**, cover every URL variant. [G](https://developers.google.com/search/docs/crawling-indexing/remove-information)
- Images: robots.txt (`Googlebot-Image`) **or** `X-Robots-Tag: noindex`, not both; `noimageindex` applies only to the page. [G](https://developers.google.com/search/docs/crawling-indexing/prevent-images-on-your-page)
- Confidential data in URLs or file names stays exposed even if blocked by robots.txt; check PDF/image metadata; staging and private areas behind authentication (`401` is the recommended practice for sites not yet launched). [G](https://developers.google.com/search/docs/crawling-indexing/keep-redacted-information-out) · [G OH 2023-03](https://developers.google.com/search/help/office-hours/2023/march)

### A/B testing and experiments
- **No cloaking**: show Googlebot the same URLs and content a user would see; do not exclude Googlebot from a test by user-agent, server logic, robots.txt or any other method. Cloaking violates the spam policies whether or not a test is running and can get a site demoted or removed. Cookie-based tests: Googlebot generally does not accept cookies, so it sees the version served to browsers that reject them. [G](https://developers.google.com/search/docs/crawling-indexing/website-testing)
- **Multi-URL tests**: put `rel="canonical"` on every alternate URL pointing to the original URL; prefer it over `noindex`, which "can sometimes have unexpected bad effects". [G](https://developers.google.com/search/docs/crawling-indexing/website-testing)
- **Redirect tests**: send users from the original URL to a variant with a **`302` (temporary)**, not a `301`, kept only while the experiment runs; JavaScript-based redirects are also acceptable. [G](https://developers.google.com/search/docs/crawling-indexing/website-testing)
- **Duration**: run the test only as long as needed (a good testing tool says when there is enough data), then remove every test element (alternate URLs, testing scripts, markup) as soon as possible. A test kept running unnecessarily long, especially with one variant served to a large share of users, may be read as an attempt to deceive search engines. [G](https://developers.google.com/search/docs/crawling-indexing/website-testing)
- JavaScript-based tests that change content on the page are fine; small changes (button size, color, placement, call-to-action text) rarely affect snippets or rankings. Google may index test variants, which usually matters little, and picks up the final version quickly once the test ends. [G](https://developers.google.com/search/docs/crawling-indexing/website-testing)

### Google crawlers and verification
- Three categories: **common** (always respect robots.txt: `Googlebot`, `Googlebot-Image`, `Googlebot-Video`, `Googlebot-News`, `Storebot-Google`, `Google-InspectionTool`, `GoogleOther*`, `Google-CloudVertexBot`, `Google-Extended` token); **special-case** (agreements with the site, may ignore robots.txt: AdsBot, Mediapartners-Google, APIs-Google, `Google-Safety`); **user-triggered** (generally ignore robots.txt: `FeedFetcher-Google`, `Google-Read-Aloud`, `Google-Site-Verification`, `GoogleMessages`, `Google-Pinpoint`, `GoogleProducer`, `Google-CWS`, `Google-GeminiNotebook`, `Google-Agent`). [G](https://developers.google.com/crawling/docs/crawlers-fetchers/overview-google-crawlers) · [G](https://developers.google.com/crawling/docs/crawlers-fetchers/google-user-triggered-fetchers)
- Blocking `Googlebot` affects Search (including Discover), Images, Video, News; blocking `GoogleOther` does not affect Search. [G](https://developers.google.com/search/docs/crawling-indexing/googlebot) · [G OH 2024-07](https://developers.google.com/search/help/office-hours/2024/july)
- **Verification** (user-agents can be spoofed): `host <IP>` → domain `googlebot.com`, `google.com` or `googleusercontent.com` → `host <name>` → same IP. At scale: CIDR JSON files `common-crawlers.json`, `special-crawlers.json`, `user-triggered-fetchers.json`, `user-triggered-fetchers-google.json`, `user-triggered-agents.json`. [G](https://developers.google.com/crawling/docs/crawlers-fetchers/verify-google-requests)
- The IP range files now live at **`developers.google.com/crawling/ipranges/`**; the old path `/search/apis/ipranges/` was due to be retired by the end of September 2026, about 6 months after the announcement of 31 March 2026 (whether the retirement happened: *(re-verify)*). [G](https://developers.google.com/search/blog/2026/03/crawler-ip-ranges)
- Crawling happens mainly from US IPs (Pacific time zone); if the US is blocked Google may try from other countries. [G](https://developers.google.com/crawling/docs/crawlers-fetchers/overview-google-crawlers)
- **Web Bot Auth** (experimental): part of the `Google-Agent` requests are signed with the identity `https://agent.bot.goog`; keep verifying with IP/DNS as well. [G](https://developers.google.com/crawling/docs/crawlers-fetchers/web-bot-auth)
- Renamed user-agents: NotebookLM became `Google-GeminiNotebook` in July 2026 (update hard-coded strings). [G](https://developers.google.com/crawling/docs/changelog)

### AI bots
- `Google-Extended`: a **robots.txt token without its own user-agent** (it never appears in logs); it controls use of content for training future Gemini generations and for grounding in Gemini apps/Vertex AI. **It does not affect inclusion in Search and is not a ranking signal.** [G](https://developers.google.com/crawling/docs/crawlers-fetchers/google-common-crawlers)
- AI Overviews and AI Mode are limited with `nosnippet`, `data-nosnippet`, `max-snippet`, `noindex` (which also limit regular snippets); to appear, the page must be indexed and eligible for a snippet. Full list of AI controls, including the Search Console setting: `ai-search.md` › Controls: what blocks what. [G](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag) · [G](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)
- `Google-Agent` (agents that browse and act for the user) and `Google-GeminiNotebook` are user-triggered fetchers: **robots.txt does not stop them**. [G](https://developers.google.com/crawling/docs/crawlers-fetchers/google-user-triggered-fetchers)
- Operators keep adding new user-agents, also for AI purposes; most commercial operators respect robots.txt. [G](https://developers.google.com/search/blog/2025/02/intro-robots-refresher)
- Third-party AI crawler tokens and how they treat robots.txt: table under [Third-party views](#third-party-views). Which bots render JavaScript: `ai-search.md` › AI crawlers and fetchers.
- Three levels of decision *(inference from third-party sources)*: **training** (can be blocked with no effect on Search), **AI search** (blocking removes the site from that service's answers), **user-triggered** (robots.txt is often not enough: WAF/server rules are needed). The owner's choice, to be made explicit.

### CDN, WAF and accidental blocks
- CDN/WAF flood protection can blocklist the crawlers you want. For temporary blocks **`503`/`429` are the best way**; **timeouts** → URLs removed and crawling reduced; **error page served with `200`** → soft error, removal or deduplication; "are you human?" interstitials → crawlers see only that: serve `503` to automated clients. [G](https://developers.google.com/search/blog/2024/12/crawling-december-cdns)
- Verification: **URL Inspection** (screenshot: blank page, error or bot check = CDN problem); allowlist with the published IPs; recheck blocklists periodically (IPs can land there automatically). [G](https://developers.google.com/search/blog/2024/12/crawling-december-cdns)
- CDNs allow higher crawl rates, but with a cold cache the origin serves every URL at least once. [G](https://developers.google.com/search/blog/2024/12/crawling-december-cdns)
- Real cases: a home page returning `404` only to Googlebot user-agents; `403` to Googlebot Smartphone; `403` on sitemaps because of IP blocking → allowlist Google's crawler ranges. [G OH 2023-01](https://developers.google.com/search/help/office-hours/2023/january) · [G OH 2023-07](https://developers.google.com/search/help/office-hours/2023/july) · [G OH 2024-04](https://developers.google.com/search/help/office-hours/2024/april)

## Build rules
1. Choose **one canonical host** (`https://` + www or apex) and redirect every variant with a `301` in one hop; valid certificate for the host. → CI-17, CI-18 [G](https://developers.google.com/search/docs/crawling-indexing/301-redirects)
2. **Minimal robots.txt**: allow everything needed (CSS, JS, APIs, images), block only useless spaces (sort orders, cart, action URLs; internal search per the decision tree in [Internal search result pages](#internal-search-result-pages)), never paginated archives, and declare the sitemap. Do not use it for privacy, removals or canonicalization. → CI-03, CI-07, CI-08, CI-09, CI-34 [G](https://developers.google.com/search/docs/crawling-indexing/robots/intro)
3. **XML sitemap generated at build time or by the CMS** with only canonical `200` URLs and real `lastmod`; stable sitemap URL. → CI-13, CI-14, CI-15 [G](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)
4. **Absolute self-referencing canonical** on every indexable page, paginated pages included; internal links, sitemap and hreflang on the same URL. → CI-22, CI-23 [G](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)
5. **True status codes**: `404`/`410` for non-existent content with a useful 404 page; `301` for moves; never error pages with `200`. → CI-26, CI-20 [G](https://developers.google.com/search/docs/crawling-indexing/troubleshoot-crawling-errors)
6. **Descriptive URLs**, lowercase, with hyphens, without session IDs, fragments or useless parameters; one URL per piece of content. → CI-25, CI-33 [G](https://developers.google.com/search/docs/crawling-indexing/url-structure)
7. **Responsive** with the same content and metadata on mobile and desktop. → CI-35 [G](https://developers.google.com/search/docs/crawling-indexing/mobile/mobile-sites-mobile-first-indexing)
8. **Multilingual**: distinct URLs per language, reciprocal hreflang with `x-default`, selector with links, no automatic redirects. → CI-36, CI-37, CI-32 [G](https://developers.google.com/search/docs/specialty/international/localized-versions)
9. **Utility pages** (thank-you, login) with `noindex`; internal search result pages per the decision tree in [Internal search result pages](#internal-search-result-pages); **staging** behind authentication (`401`) and not linked. → CI-09, CI-38 [G](https://developers.google.com/search/docs/crawling-indexing/block-indexing) · [G OH 2023-03](https://developers.google.com/search/help/office-hours/2023/march)
10. **Server**: `ETag`/`Last-Modified` with `304`, compression, stable response times; no geo-blocking. → CI-40, CI-41, CI-28, CI-32 [G](https://developers.google.com/search/blog/2024/12/crawling-december-caching)
11. **CDN/WAF**: allowlist the wanted crawlers with the published IPs, `503`/`429` for temporary blocks, no challenges for crawlers; review the CDN's AI-bot settings. → CI-30, CI-31, CI-44 [G](https://developers.google.com/search/blog/2024/12/crawling-december-cdns)
12. **AI bots**: decide explicitly on training/search/user-triggered and write it in robots.txt (+ WAF where robots.txt is not enough); for sites that want visibility, default *(inference)*: do not block search bots. → CI-45 [G](https://developers.google.com/search/blog/2025/03/robotstxt-flexible-way-to-control)
13. **At launch**: remove every development `noindex`/`Disallow: /`, verify the Domain property in Search Console, submit the sitemap, run URL Inspection on key pages; expect days or weeks. → CI-03, CI-10, CI-50 [G](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl)
14. **Experiments**: same content for Googlebot and users, `rel="canonical"` to the original on variant URLs, `302` for redirect tests, remove the test once it has enough data. → CI-51, CI-52, CI-53, CI-54 [G](https://developers.google.com/search/docs/crawling-indexing/website-testing)

## Notes by site type
- **ecommerce**: faceted navigation and parameters are the first source of over-crawling; variants with their own URLs and a canonical to the product; empty categories `noindex` or `404`; permanently sold-out products → `404` or redirect to the equivalent replacement; category pagination crawlable and self-canonical (see [Pagination](#pagination)); crawl budget and `304` become relevant above the thresholds. [G](https://developers.google.com/crawling/docs/faceted-navigation) · [G](https://developers.google.com/search/docs/specialty/ecommerce/designing-a-url-structure-for-ecommerce-sites)
- **editorial**: pagination with its own URLs, each canonical to itself, crawlable and linked with `<a href>`; do not `Disallow` or `nofollow` `/page/N` archives (see [Pagination](#pagination)); `lastmod` only for substantial changes; News sitemap only for publishers in Google News. [G OH 2022-11](https://developers.google.com/search/help/office-hours/2022/november) · [G](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading)
- **local-business**: one page per real location (no cloned city pages); booking calendars with a URL per date → robots.txt or `nofollow`; holiday closures with a banner, not with prolonged `503`s or `noindex`; every external profile (Business Profile, social) should link to the site. [G](https://developers.google.com/search/docs/crawling-indexing/pause-online-business) · [G OH 2023-12](https://developers.google.com/search/help/office-hours/2023/december)
- **personal-brand**: small site → crawl budget irrelevant; a sitemap is still useful because the site is new and has few links. Demos and projects on subdomains have their own robots.txt and budget: make test environments non-indexable. A CV in PDF is indexable (up to 64 MB); to exclude it use `X-Robots-Tag: noindex`, not robots.txt; put a link to the site at the top of the PDF. Moving from a platform subdomain to an own domain (e.g. `adanovak.github.io` → `adanovak.example`) is a migration with 1:1 `301`s. [G](https://developers.google.com/crawling/docs/crawl-budget) · [G OH 2023-12](https://developers.google.com/search/help/office-hours/2023/december)
- **professional-services**: one page per real service (no cloned city pages); booking calendars and closures as for local-business; external profiles (directories, LinkedIn, social) should link to the site. [G](https://developers.google.com/search/docs/crawling-indexing/pause-online-business) · [G OH 2023-12](https://developers.google.com/search/help/office-hours/2023/december)

## Third-party views
- [SEJ 2026-04, Illyes/Splitt podcast] Google supports only 4 robots.txt fields; it said it would document the 10–15 most used unsupported rules and might tolerate `disallow` typos. A frequent SPA error: robots.txt returning the fallback HTML.
- [SEJ 2026-07, news on Google docs] robots.txt documentation updated: the specific user-agent group prevails over `*`. Consistent with the spec.
- [SEJ 2026-07, Mueller] Shared claude.ai pages blocked in robots.txt but carrying `X-Robots-Tag: none` were indexed: the disallow prevented Google from seeing the noindex. Confirms Google.
- [SEJ 2026-01, Mueller] "Phantom noindex" in Search Console: the noindex was really there, but only for Google; the author's hypothesis: a CDN cache serving old headers to Googlebot.
- [SEJ 2026-01, Mueller] "Page indexed without content" usually indicates a server/CDN block (also by IP), not JavaScript; often reproducible only with Search Console tools.
- [SEJ 2026-07, Mueller podcast] "Are you a bot?" screens served with `200` can get the page indexed as a duplicate of other sites, with someone else's canonical. Confirms the Google blog post on CDNs.
- [SEJ 2026-02, Mueller] A default HTTP page left active next to HTTPS: Chrome upgrades to HTTPS, Googlebot does not → wrong site name and favicon. Check with `curl http://`.
- [SEJ 2026-02, Illyes/Splitt] Robots meta and canonical are valid **only in the `<head>`** (accepting them in the body would allow hijacking). This conflicts with the robots meta tag documentation, which says Google also respects the tag in the body; the operational rule (always in the head) satisfies both.
- [SEJ 2026-04, Mueller] 9 scenarios of canonical selection (duplicates, dominant template, parameter patterns, mobile version, bot-challenge page, failed JS rendering, system errors).
- [SEJ 2026-07, Mueller] There is no public order of precedence between conflicting sources (HTML, JSON-LD, feeds; visible date vs `dateModified` vs `lastmod`): align them, do not test them.
- [SEJ 2026-09, Mueller] Child sitemaps with a daily `?v=timestamp` to force refetching: a bad idea; use stable URLs and an accurate `lastmod`.
- [SEJ 2026-08, news on Google docs] Crawl budget guide rewritten: capacity shared between crawlers, `304` recommended. Consistent with Google.
- [SEJ 2026-06, news on Google docs] Change of Address must be submitted for every subdomain and www/non-www variant of the old domain. Consistent with Google.
- [SEJ 2026-03, Mueller] `404`s in Search Console are not a problem; a `410` does not change the recheck frequency.
- [SEJ 2026-07, Southern/Cloudflare news] Cloudflare classifies bots as Search, Agent, Training; **since 15 September 2026** new domains with advertising block Training and Agent by default; multi-purpose crawlers (Googlebot, Applebot, Bingbot) get the most restrictive rule, so **blocking "Training" (also the old "Block AI bots") can block Googlebot**. A vendor's rule, not Google's.
- [SEJ 2026-08, Reddit report] `403` to Googlebot/Bingbot on the sitemap with "AI Training = Block" or Bot Fight Mode; cause not confirmed (Mueller asked for details).
- [SEJ 2026-09, Manić / Southern] Cloudflare "Bot Preference Sync" writes robots.txt per category; a new "Disallow AI Training" option publishes the no-training signal (via `Google-Extended`, `Applebot-Extended`) without blocking Googlebot. It does not affect AI Overviews/AI Mode. Cloudflare has blocked AI crawlers by default on new domains since 1 July 2025 [SEJ 2025-11, 2026-08].
- [SEJ 2026-07, Pollitt / opinion] Three classes of AI bots; OpenAI no longer guarantees that `ChatGPT-User` respects robots.txt, nor does Perplexity for `Perplexity-User`; for small sites it is better not to block search bots and to decide only on training. Conflicting: [SEJ 2026-05, Manić] writes that `ChatGPT-User`/`Claude-User` respect robots.txt. *(re-verify)* on the vendors' documentation.
- [SEJ 2026-09, Ask an SEO / opinion] robots.txt is voluntary: for real blocks use WAF > CDN > server; risk of an accidental `Disallow: /`.
- [SEJ 2026-06, Forrester / single case, commercial interest] On a new site ~82% of "AI live-fetch" requests and ~87% of "Googlebot" requests were fake (IP verification); `Google-Extended` does not appear in logs.
- [SEJ 2026-08, single case] A fake `CCBot` was probing for sensitive files (`.env`, SSH keys): verify IPs before attributing traffic.
- [SEJ 2025-12, Cloudflare Year in Review] Googlebot reached 11.6% of unique pages, GPTBot 3.6%, ClaudeBot 2.4%; "user-action" crawling grew > 15x; GPTBot, ClaudeBot, CCBot were the most blocked. [SEJ 2026-01, Hostinger] GPTBot coverage fell from 84% to 12%, OAI-SearchBot reached up to 68%. Descriptive vendor data.
- [SEJ 2026-04/2026-07, Cloudflare data] Very unbalanced crawl/referral ratios (ClaudeBot from ~20,600:1 to 70,900:1 depending on the period, Google ~9.4:1). Figures vary between articles *(re-verify)*.
- [SEJ 2026-07/2026-08, Google news] Search Console option to opt out of generative AI features: see `ai-search.md` › Controls: what blocks what, which owns its status.

## Myths and outdated advice
- `crawl-delay`, `noindex:` or `clean-param` in robots.txt for Google → not supported. [G](https://developers.google.com/search/blog/2025/03/robots-future)
- "Blocked in robots.txt = out of Google" → it can stay indexed as a bare URL; use `noindex` with crawling allowed. [G](https://developers.google.com/search/docs/crawling-indexing/robots/intro)
- "`noindex` + `Disallow` to be safe" → the noindex is never read. [G](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag)
- "`noindex` saves crawl budget" → no, the page still has to be requested. [G](https://developers.google.com/crawling/docs/crawl-budget)
- "404s harm the site / they must all be redirected" → they are normal; redirect only to equivalent replacements. [G OH 2024-08](https://developers.google.com/search/help/office-hours/2024/august)
- "Duplicate content penalty" → does not exist; duplicates do not violate the policies. [G](https://developers.google.com/search/help/crawling-index-faq)
- `<priority>` and `<changefreq>` in the sitemap → ignored. [G](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)
- "The sitemap guarantees indexing" / "compressing it increases budget" → false. [G](https://developers.google.com/search/help/crawling-index-faq) · [G](https://developers.google.com/crawling/docs/myths-about-crawling)
- "Constant edits or updated dates to look fresh" → useless. [G](https://developers.google.com/crawling/docs/myths-about-crawling)
- "Small sites get crawled less" / "crawl budget always needs care" → false below the thresholds. [G](https://developers.google.com/crawling/docs/myths-about-crawling)
- "URLs without parameters are preferred" → Google crawls parameters; what matters is consistency and no infinite spaces. [G](https://developers.google.com/crawling/docs/myths-about-crawling)
- "Put paginated archives (`/page/N`) in `Disallow` or canonicalize them to page 1" → keep them crawlable and self-canonical (see [Pagination](#pagination)). [G](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading)
- `rel="next"`/`rel="prev"` → no longer used. [G](https://developers.google.com/search/docs/crawling-indexing/special-tags)
- `noarchive` (cache copy removed), `nositelinkssearchbox`, `noodp`, `meta keywords` → no effect. [G](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag) · [G](https://developers.google.com/search/docs/crawling-indexing/special-tags)
- "`401`/`403` to slow Googlebot down" → wrong: use `503`/`429` for short periods or the crawl-rate reduction form. [G](https://developers.google.com/crawling/docs/crawlers-fetchers/reduce-crawl-rate)
- "HTTP/2, HTTP/3, HSTS give a ranking boost" → no. [G](https://developers.google.com/crawling/docs/crawlers-fetchers/overview-google-crawlers) · [G OH 2023-06](https://developers.google.com/search/help/office-hours/2023/june)
- "Blocking `Google-Extended` removes the site from AI Overviews" / "it is needed to stay in Search" → no: it concerns only Gemini (training/grounding). [G](https://developers.google.com/crawling/docs/crawlers-fetchers/google-common-crawlers)
- "Geotargeting in Search Console" → no longer exists; use ccTLD/hreflang/local signals. [G OH 2024-08](https://developers.google.com/search/help/office-hours/2024/august)
- "`lang` attribute or geo meta tags for targeting" → ignored by Google. [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)
- "Requesting indexing several times speeds it up" → no; there is a quota. [G](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl)
- IP path `/search/apis/ipranges/` → replaced by `/crawling/ipranges/` (old path due to be retired by the end of September 2026 *(re-verify)*). [G](https://developers.google.com/search/blog/2026/03/crawler-ip-ranges)
- llms.txt for Google Search → not used, neither positive nor negative. [G](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)
