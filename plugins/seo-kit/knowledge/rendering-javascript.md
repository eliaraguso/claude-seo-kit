## Facts and rules (Google)

### Google's pipeline
- Google processes JS apps in three phases: **crawling → rendering → indexing**, with separate queues for crawling and rendering; you cannot see which queue a page is in. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
- Rendering uses **evergreen Chromium** (headless, always on the latest stable version). [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
- Before each request Googlebot reads robots.txt: if the URL is blocked it skips the request; **Google does not run JS from blocked files or on blocked pages**. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
- **Every page with HTTP `200` goes to the render queue**, with or without JS, unless a robots meta tag or header says not to index it. The wait ranges from seconds to longer. With a status other than `200` (e.g. `404`) rendering **may be skipped**. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
- After rendering, Google parses the links in the rendered HTML again and **uses the rendered HTML for indexing**. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
- Technical flow: Googlebot downloads the HTML → passes it to the **Web Rendering Service (WRS)** → the WRS, through Googlebot, downloads JS, CSS and XHR; long periods can pass between the steps. [G](https://developers.google.com/search/blog/2024/12/crawling-december-resources)
- Every page that crawls successfully is rendered (a 404 is not). Live tests (URL Inspection, Rich Results Test) **ignore the cache** and can time out, so the rendered HTML in a test can differ from the one used for indexing. [G OH 2023-05](https://developers.google.com/search/help/office-hours/2023/may)
- Canonicalisation **does not differ** between CSR and non-CSR sites: it uses the same signals. [G OH 2023-07](https://developers.google.com/search/help/office-hours/2023/july)
- Google states that SEO for sites built with JS frameworks is "generally more complex" and points to the JS best practices for generative AI features too (AI Overviews, AI Mode). [G](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)

### Rendering strategies
- **Server-side rendering or pre-rendering is still "a great idea"**: faster for users and crawlers, and **not all bots can run JavaScript**. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
- **Dynamic rendering** (pre-rendered HTML for bots, CSR for users, chosen by user agent) = **a workaround, not recommended as a long-term solution** (complexity, resources). Recommended: **SSR, static rendering, hydration**. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/dynamic-rendering)
- Dynamic rendering is not cloaking if the content is similar; it is cloaking if bots and users see completely different content. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/dynamic-rendering) · It is not recommended for new projects; if it already works there is no need to change it. [G OH 2023-05](https://developers.google.com/search/help/office-hours/2023/may)
- **App shell** model (initial HTML without content): Google has to run JS to see the content. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
- The backend or framework does not affect ranking by itself; performance and behaviour do. [G OH 2023-05](https://developers.google.com/search/help/office-hours/2023/may) · JS frameworks (e.g. Next.js) work well when configured; **set up SEO before launch**, fixing it afterwards is much harder. [G OH 2024-06](https://developers.google.com/search/help/office-hours/2024/june)

### Routing and URLs
- **Use the History API**, not fragments: Google reliably resolves only `<a href="/products">`; the example `<a href="#/products">` + `hashchange` is listed as bad practice. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
- The **AJAX crawling scheme** (`#!`) has been deprecated since 2015. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/fix-search-javascript)
- `#` fragments must not change the content: they are generally not supported; with JS use the History API. [G](https://developers.google.com/search/docs/crawling-indexing/url-structure) · Search generally ignores fragments. [G OH 2023-08](https://developers.google.com/search/help/office-hours/2023/august)
- In SPAs with a single HTML page, **every screen or piece of content needs its own URL**. [G](https://developers.google.com/search/docs/fundamentals/get-started-developers)
- Deliberate exception: for filters/facets you do **not** want indexed, fragments are a valid way to keep them from being crawled. [G](https://developers.google.com/crawling/docs/faceted-navigation)
- Routers, libraries and third-party scripts **must not manipulate the history** (`pushState`/`replaceState`) so that users cannot go straight back: "back button hijacking" has been a harmful (spam) practice **since 15 June 2026**. [G](https://developers.google.com/search/blog/2026/04/back-button-hijacking)

### Crawlable links
- Google extracts URLs from the **`href` attribute of `<a>` elements**; links inserted with JS are fine if they use this markup. Accepted values: absolute, relative `/…`, `./…`; also accepted with `onclick` or classes. [G](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)
- Not recommended (Google might still try): `<a routerLink="products/category">` without `href`, `<span href>`, `<a onclick="goto()">`, `href="javascript:…"`. [G](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)
- **Googlebot generally does not click buttons** and does not trigger JS that needs interaction. [G OH 2023-09](https://developers.google.com/search/help/office-hours/2023/september) · [G](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading)
- `<option value="URL">` items of a `<select>` **are not links**. [G OH 2023-05](https://developers.google.com/search/help/office-hours/2023/may) · Hover menus work if the links are `<a href>` already in the HTML. [G OH 2022-12](https://developers.google.com/search/help/office-hours/2022/december)
- Anchor text: visible, non-empty text; for image links the `alt` counts; if the anchor is inserted with JS, check the rendered HTML. [G](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)
- To stop a link from being discovered: `nofollow`. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)

### Status codes and soft 404s in SPAs
- Use meaningful HTTP codes: `404` for a page that does not exist, `401` for pages behind a login, redirects for moved pages. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
- In SPAs with client-side routing the server often answers `200` to any URL → **soft 404**. Google's two solutions: (1) a **JS redirect** to a URL for which the server responds `404` (e.g. `/not-found`); (2) add **`<meta name="robots" content="noindex">`** to the error page with JS. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
- `<meta name="prerender-status-code" content="404">` is **ignored** by Googlebot. [G OH 2023-12](https://developers.google.com/search/help/office-hours/2023/december)
- A page that returns `200` but looks like an error (empty, error message, JS not loaded, blocked resources) is classified as a **soft 404**; resources that fail to load can leave it empty. [G](https://developers.google.com/search/docs/crawling-indexing/troubleshoot-crawling-errors)
- For facets with no results Google asks for a `404` on the URL itself, not a redirect to a shared 404 page, **except in SPAs** where that may not be possible. [G](https://developers.google.com/crawling/docs/faceted-navigation)

### Metadata managed by JavaScript
- `<title>` and meta description can be set or changed with JS. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
- **Canonical**: the best place is the HTML; if you use JS, **use the same value as the original HTML**; do not use JS to change it to a different URL; if you cannot set it in the HTML, **leave it out of the HTML** and set it only with JS. There must remain **a single** `rel="canonical"`: faulty implementations create several or modify the existing one → unexpected results. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics) · [G](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)
- **Robots meta tag**: can be added or changed with JS (e.g. `noindex` when the API returns an error). But when Google finds `noindex` it **may skip rendering and JS execution**: removing with JS a `noindex` present in the original HTML may not work. If the page should be indexed, **no `noindex` in the original code**. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
- Meta tags in general: **avoid inserting or changing them with JS** when possible; if you must, test thoroughly. [G](https://developers.google.com/search/docs/crawling-indexing/special-tags)
- `data-nosnippet`: extraction can happen before or after rendering → **do not add or remove it with JS on existing nodes**; if the node is created with JS, include it from the start. Valid only on `span`, `div`, `section`. [G](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag)
- Valid `<head>`: if an invalid element appears (e.g. `iframe`, `img`) Google assumes the head has ended and **ignores the elements that follow**. Valid: `title`, `meta`, `link`, `script`, `style`, `base`, `noscript`, `template`. [G](https://developers.google.com/search/docs/crawling-indexing/valid-page-metadata)
- **JSON-LD** can be generated and inserted with JS; test it. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics) · [G](https://developers.google.com/search/docs/appearance/structured-data/generate-structured-data-with-javascript)
- **JS redirects** (`window.location`): allowed and interpreted as permanent, but only when a server-side or meta refresh redirect is not possible; rendering can fail and Google **might never see** the redirect. [G](https://developers.google.com/search/docs/crawling-indexing/301-redirects)

### Lazy loading and interactions
- Load content when it enters the **viewport**: native lazy loading (images, iframes), **IntersectionObserver**, viewport-based libraries. Do **not** rely on scrolling, clicking or typing: Google does not interact. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/lazy-loading)
- Do **not** lazy-load content that is visible immediately. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/lazy-loading)
- Indexable infinite scroll: chunks with a **unique, permanent URL**, absolute page numbers (`?page=12`, not `?date=yesterday`), sequential links to the individual URLs, URL updated with the History API. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/lazy-loading) · Google renders like a very tall device ("viewport expansion"): without pagination it may not see endless content. [G OH 2023-03](https://developers.google.com/search/help/office-hours/2023/march)
- Content that appears only after scroll events (scrolljacking) risks being treated as not visible. [G OH 2023-09](https://developers.google.com/search/help/office-hours/2023/september)
- Mobile-first: no lazy loading of primary content tied to interaction; accordions and tabs are fine if the content is in the DOM. [G](https://developers.google.com/search/docs/crawling-indexing/mobile/mobile-sites-mobile-first-indexing)
- Test: if after rendering the image/video URLs are in the `src` attributes of `<img>`/`<video>`, it works. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/lazy-loading)

### Limits and the WRS
- **Googlebot (Search) fetches the first 2 MB** of a supported file type and **64 MB of a PDF**; the limit applies to **uncompressed data** and **includes the HTTP headers**. Each referenced resource (CSS, JS, XHR) is fetched separately with **the same 2 MB limit** (its own counter). Past the threshold the fetch stops and the downloaded part is treated as the complete file; the rest is not fetched, rendered or indexed. [G](https://developers.google.com/search/docs/crawling-indexing/googlebot) · [G](https://developers.google.com/search/blog/2026/03/crawler-blog-post)
- Other Google crawlers without their own limit: **15 MB** by default. The limit "may change over time". [G](https://developers.google.com/crawling/docs/crawlers-fetchers/overview-google-crawlers) · [G](https://developers.google.com/search/blog/2026/03/crawler-blog-post)
- Typical risks: **inline base64** images, huge blocks of **inline CSS/JS**, megabytes of menu before the content. Advice: lean HTML, heavy CSS/JS in external files, **title, meta, links, canonical and essential structured data near the top**. [G](https://developers.google.com/search/blog/2026/03/crawler-blog-post)
- The WRS runs JS, CSS and XHR (not images/video) and **only the code actually fetched**. [G](https://developers.google.com/search/blog/2026/03/crawler-blog-post)
- **The WRS is stateless**: it clears **localStorage, sessionStorage and HTTP cookies** between page loads; it follows server and client redirects like a browser. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/fix-search-javascript)
- Googlebot declines **permission** requests (e.g. Camera API): content must not depend on consent. Googlebot **does not support WebSockets or WebRTC** (provide an HTTP fallback) or **WebGL** (feature detection, fallback or pre-render). [G](https://developers.google.com/search/docs/crawling-indexing/javascript/fix-search-javascript)
- **Web components**: the WRS flattens light DOM and shadow DOM; Google sees only what is in the rendered HTML; use `<slot>`. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
- Googlebot may not fetch non-essential resources (beacons, error reporting): client-side analytics **do not** represent Googlebot activity (use the Crawl Stats report). [G](https://developers.google.com/search/docs/crawling-indexing/javascript/fix-search-javascript)
- Googlebot crawls mostly from **US IP addresses** and **does not send `Accept-Language`**: content adapted by IP or browser language may not be seen in its variants. [G](https://developers.google.com/search/docs/specialty/international/locale-adaptive-pages)

### Resources, robots.txt and caching
- **Do not block in robots.txt** the JS, CSS and XHR/API endpoints needed for rendering: if the WRS cannot fetch them, Google may fail to extract the content. [G](https://developers.google.com/search/blog/2024/12/crawling-december-resources) · If CSR content depends on an API, Googlebot must be able to reach it. [G OH 2023-05](https://developers.google.com/search/help/office-hours/2023/may)
- Crawling rendering resources **uses the crawl budget of the host that serves them**; embedded XHR/CSS/JS use budget too. [G](https://developers.google.com/search/blog/2024/12/crawling-december-resources) · [G](https://developers.google.com/crawling/docs/myths-about-crawling)
- **The WRS caches JS and CSS for up to 30 days, ignoring HTTP caching headers** → use **file-name fingerprinting** (e.g. `main.2bb85551.js`); use cache-busting parameters with care (a new URL means a new download even when the content is identical). [G](https://developers.google.com/search/blog/2024/12/crawling-december-resources) · [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
- Hosting **critical resources** (rendering JS/CSS) on a separate host is **not recommended** (connection overhead; correction of 6 December 2024); fine for large non-critical resources. [G](https://developers.google.com/search/blog/2024/12/crawling-december-resources)
- URLs discovered in JSON/JS (e.g. API paths that return 404) can be blocked in robots.txt; those 404s do not end up in the index. [G OH 2023-12](https://developers.google.com/search/help/office-hours/2023/december)

### Content Google does not see
- Content that needs **plug-ins** or is drawn in **`<canvas>`** is not indexed; text inserted with CSS **`content`** is not part of the DOM and is ignored. [G](https://developers.google.com/search/docs/fundamentals/get-started-developers)
- Text inside images: not used for web results → put it in HTML text or `alt`. [G OH 2022-12](https://developers.google.com/search/help/office-hours/2022/december)
- A **JS paywall** that sends all the content and hides it with JS is not reliable: serve the full content only after the subscription has been verified. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/fix-search-javascript)
- Linking variants only for Googlebot and not for users = cloaking. [G OH 2024-06](https://developers.google.com/search/help/office-hours/2024/june)

### Non-Google bots and JavaScript
- Google fact: **"not all bots can run JavaScript"**; other search engines may ignore it. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics) · [G](https://developers.google.com/search/docs/crawling-indexing/javascript/dynamic-rendering)
- Which AI and third-party crawlers render JavaScript is not documented by Google; the third-party tests, their evidence level and their disagreement over CCBot are kept in one place: the bot table of `ai-search.md`. Practical consequence *(inference)*: if the goal includes ChatGPT, Claude or Perplexity, essential content must be in the initial HTML (SSR/SSG/prerender), which is in any case the route Google recommends.
- Do not serve bots a different version (without JS, Markdown): Google recommends the same content for everyone; "bot" versions with different content = cloaking. [G](https://developers.google.com/search/docs/essentials/spam-policies) · [G](https://developers.google.com/search/docs/crawling-indexing/javascript/dynamic-rendering)

### Testing tools
- **URL Inspection** (Search Console, verified owners only): rendered HTML, screenshot, loaded/blocked resources, JS console, exceptions; **Rich Results Test** (anonymous, any URL or pasted code). [G](https://developers.google.com/search/docs/crawling-indexing/javascript/fix-search-javascript) · [G](https://developers.google.com/search/help/debug)
- Local pages or pages behind a firewall: expose them through a tunnel (e.g. `ngrok`); Google's tools **respect robots.txt**, so tunnels that serve a restrictive robots.txt cannot be tested. [G](https://developers.google.com/search/help/debug)
- Optional JS error collection: `window.addEventListener('error', …)` to a logging endpoint (does not catch parse errors). [G](https://developers.google.com/search/docs/crawling-indexing/javascript/fix-search-javascript)
- Compare **curl (raw HTML) vs rendered DOM** *(inference: the standard method to separate what the server sends from what JS creates)*: `curl -sL -A "<UA>" URL` vs the DOM from a headless browser (DevTools Elements, Puppeteer/Playwright, `chrome --headless --dump-dom URL`). URL Inspection remains the official reference.
- To check what the server really serves to Google (CDN, varying headers): Rich Results Test (UA `Google-InspectionTool`, Google IP addresses). [G](https://developers.google.com/crawling/docs/crawlers-fetchers/google-common-crawlers) · `Google-InspectionTool` **does not follow redirects**: test the final URL. [G](https://developers.google.com/crawling/docs/troubleshooting/http-status-codes)

## Build rules
1. **Rendering**: for pages to be indexed choose **SSG/prerender** (content that changes little) or **SSR** (dynamic content); pure CSR only for non-indexable areas (dashboards, accounts). Do not use dynamic rendering. → RJ-01, RJ-28 [G](https://developers.google.com/search/docs/crawling-indexing/javascript/dynamic-rendering)
2. **URLs**: a real URL for every indexable view, with the History API; never `#/`. → RJ-03, RJ-04 [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
3. **Links**: navigation only with `<a href>` (framework link components that output `<a>`), descriptive anchors. → RJ-05 [G](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)
4. **Status codes**: the server returns `404` for unknown routes and non-existent resources; with pure CSR use a JS redirect to a `404` URL or `noindex` via JS. → RJ-06, RJ-07, RJ-30 [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
5. **Metadata per route**: title, description, absolute canonical (only one), robots, hreflang and JSON-LD produced **in the served HTML** and near the top; no `noindex` in the base template. → RJ-08, RJ-09, RJ-10, RJ-11, RJ-14, RJ-17 [G](https://developers.google.com/search/blog/2026/03/crawler-blog-post)
6. **Weight**: HTML and every bundle well below 2 MB uncompressed; no base64 images or huge serialised state inline. → RJ-15, RJ-16, RJ-17 [G](https://developers.google.com/search/docs/crawling-indexing/googlebot)
7. **No state**: content does not depend on storage, cookies, permissions, previous visits or geolocation. → RJ-19, RJ-31 [G](https://developers.google.com/search/docs/crawling-indexing/javascript/fix-search-javascript)
8. **Lazy loading** only below the fold and viewport-based; no indexable content loaded on click/hover. → RJ-21, RJ-22, RJ-23 [G](https://developers.google.com/search/docs/crawling-indexing/javascript/lazy-loading)
9. **Assets** with a content hash in the file name; critical JS/CSS on the same host; robots.txt that does not block assets or APIs. → RJ-18, RJ-24, RJ-25 [G](https://developers.google.com/search/blog/2024/12/crawling-december-resources)
10. **Hosting**: configure the SPA fallback so that `/robots.txt`, `/sitemap.xml` and unknown URLs do **not** receive `index.html` with `200` → RJ-06, CI-02 *(inference from [G](https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec) and [G](https://developers.google.com/search/docs/crawling-indexing/troubleshoot-crawling-errors))*.
11. **History**: the router must not trap the user (back button hijacking). → RJ-29 [G](https://developers.google.com/search/blog/2026/04/back-button-hijacking)
12. **Verify before launch**: URL Inspection / Rich Results Test (through a tunnel if local), curl vs rendered comparison, automated tests in CI. → RJ-02, RJ-34 [G](https://developers.google.com/search/help/debug)

## Notes by site type
- **ecommerce**: prices, availability and variants in the rendered DOM and consistent with the structured data; non-indexable facets kept out with fragments or robots.txt; "load more" backed by paginated URLs; cart and actions must not generate crawlable URLs. [G](https://developers.google.com/crawling/docs/faceted-navigation)
- **editorial**: SSG; archives and categories paginated with `<a href>`; infinite scroll only with paginated URLs; dates and author consistent between HTML and JSON-LD. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/lazy-loading)
- **local-business**: name, address, phone, opening hours, services and prices as **text in the initial HTML**, not only in JS widgets, images or PDFs; contact/booking forms with real `<a>`/`<button>`/`<label>` elements *(inference; third-party views in [SEJ 2026-09](#third-party-views))*. No content adapted by IP geolocation on the same URL. [G](https://developers.google.com/search/docs/specialty/international/locale-adaptive-pages)
- **personal-brand**: every project and article on its own stable URL (e.g. `adanovak.example/projects/project-name`), not modals or hash tabs; prerender/SSG is the simplest choice; case-study text in HTML (not only screenshots/canvas/video). [G](https://developers.google.com/search/docs/fundamentals/get-started-developers)
- **professional-services**: as local-business for services, prices and contact forms in the initial HTML with real form elements; no content adapted by IP geolocation on the same URL. [G](https://developers.google.com/search/docs/specialty/international/locale-adaptive-pages)

## Third-party views
- [SEJ 2025-12, news on Google docs] Google updated its JS documentation twice: an initial `noindex` can prevent rendering; the canonical is evaluated **on both the raw and the rendered HTML** → set it identically in both, or only via JS. Consistent with Google, although the current Google page does not state the dual evaluation explicitly (checked 2026-10-11).
- [SEJ 2026-03, news on Google docs] Google **removed** the "design for accessibility" section (testing with JS disabled, text browsers) from its JS guide as "outdated": for Google, loading content with JS "doesn't make things harder". The extra rendering phase and the speed advantage of SSR remain. See [Myths and outdated advice](#myths-and-outdated-advice).
- [SEJ 2026-07, Dave Smart test + Splitt statement] The "5-second rendering limit" is a **myth**: it was the median queue wait (90th percentile: a few minutes); in a test with APIs delayed by 6–12 s the content was indexed (the WRS uses a virtual clock). A single test: it does not prove the absence of every limit.
- [SEJ 2026-04, Mueller on Reddit] Among the causes of a "wrong" canonical: if Google cannot render a JS framework it may use the bootstrap HTML, identical for every route → pages treated as duplicates.
- [SEJ 2026-09, Mueller] A JS error shell ("Application error…") served during outages led to URLs being grouped as duplicates and de-indexed; advice: automated pre-deploy tests and frequent monitoring.
- [SEJ 2026-02, Mueller] A page showed "unavailable" in the HTML and "available" after JS: Google indexed the initial text and AI answers reported the site as offline. Do not swap text with JS; load the whole block.
- [SEJ 2026-02, Illyes/Splitt podcast] Robots meta and canonical are valid **only in the `<head>`**; a script that injects an iframe into the head closes the head and moves hreflang into the body, where it is ignored. Conflict: Google's robots meta tag documentation says Google also respects robots meta tags placed in the `<body>` [G](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag). Resolution: always place robots meta, canonical and hreflang in the `<head>` (→ RJ-10); a robots meta found in the body may still be honoured.
- [SEJ 2026-02, Illyes/Splitt] Googlebot does not benefit from resource hints (`preload`, `prefetch`, `preconnect`, `dns-prefetch`); they remain useful for users and Core Web Vitals.
- [SEJ 2026-02, HTTP Archive data + Mueller] Median raw HTML 33 KB, 90th percentile ~151–155 KB: exceeding 2 MB is rare. Correction: the article says the limit concerns the HTML "and not external JS/CSS files"; for Google each JS/CSS file has its own 2 MB limit too.
- Which AI bots run JavaScript (Vercel 2024 test, Cloudflare data, Common Crawl statements; sources disagree on CCBot): see the bot table in `ai-search.md`, which owns this topic.
- [SEJ 2026-06, Web Performance Tools study, 274 fintech homepages] 36% had less than 80% of the content in the raw HTML, 47 sites served an empty shell; 101 were at 100% (not tied to the stack). Homepages only, one day, one origin.
- [SEJ 2026-09, Shaw/Jeffery webinar] Review widgets loaded with JS are invisible to AI systems: write the number of reviews and the rating as text. Opinion, no data.
- [SEJ 2026-04, Manić] ⚠ Proposal to serve bots a "no-JS" version: cloaking risk, against Google's line (same content for everyone via SSR/prerender).
- [SEJ 2026-02/2026-06, Mueller/Splitt] Parallel Markdown versions for bots = technical debt and invisible failures (compared to dynamic rendering); Google Search ignores them.

## Myths and outdated advice
- "Google does not run JavaScript" → false: it does, with evergreen Chromium, in a separate phase. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
- "If it works in Google, the other bots will cope" → Google itself says not all bots run JS. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
- AJAX `#!` scheme / `_escaped_fragment_` → deprecated since 2015. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/fix-search-javascript)
- Dynamic rendering as the recommended solution → only a workaround, not recommended for new projects. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/dynamic-rendering)
- `prerender-status-code` meta → ignored. [G OH 2023-12](https://developers.google.com/search/help/office-hours/2023/december)
- "I put `noindex` in index.html and remove it with JS on the good pages" → may not work: Google can skip rendering. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
- "I change the canonical with JS after load" → not recommended; same value, or set only via JS. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
- "Google has a 5-second rendering timeout" → myth (see [Third-party views](#third-party-views)).
- "Testing with JS disabled = how Google sees the page" → removed from Google's JS guide in March 2026 [SEJ 2026-03]; it does not represent Googlebot. Some third parties still propose "disable JavaScript in DevTools and reload: what you see is what the agent sees" as a proxy for AI bots that do not render JS [SEJ 2026-04/2026-06, Manić]; for that question use the `ai-search.md` bot table and RJ-32.
- `rel="next"`/`rel="prev"` for pagination → no longer used by Google. [G](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading)
- Resource hints to help Googlebot → no benefit for crawling [SEJ 2026-02, Illyes/Splitt].
- Moving critical JS/CSS to a separate CDN/subdomain to save crawl budget → not recommended for performance (December 2024). [G](https://developers.google.com/search/blog/2024/12/crawling-december-resources)
- Client-side analytics to measure Googlebot → not reliable; use server logs and the Crawl Stats report. [G](https://developers.google.com/search/docs/crawling-indexing/javascript/fix-search-javascript)
- llms.txt, Markdown or "for AI" versions of pages → ignored by Google Search, neither positive nor negative. [G](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)
- "You must validate HTML with the W3C for ranking" → no; only a valid `<head>` matters. [G](https://developers.google.com/search/help/crawling-index-faq) · [G](https://developers.google.com/search/docs/crawling-indexing/valid-page-metadata)
