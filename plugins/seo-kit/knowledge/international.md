## Facts and rules (Google)

### Multilingual vs multi-regional
- **Multilingual** = content in more than one language; Search tries to match the searcher's language. **Multi-regional** = content explicitly aimed at users in different countries; Search tries to show the right locale page. A site can be both. [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)
- Targeting a site or section to one country and language can improve rankings there "at the expense of results in other locales or languages". Expect some users to land on the "wrong" version anyway: show region and language selectors on every page. [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)

### Choosing the URL structure
Google lists four options, with these pros and cons (wording condensed from the page): [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)

| Option | Example | Pros (Google) | Cons (Google) |
|---|---|---|---|
| Country-code domain (ccTLD) | `acme-widgets.de` | Clear geotargeting; server location irrelevant; easy separation of sites | Expensive, availability may be limited; more infrastructure; strict ccTLD requirements in some countries; one country only |
| Subdomain on a gTLD | `de.acme-widgets.example` | Easy to set up; servers can be in different locations; easy separation | Users may not tell whether "de" means the language or the country |
| Subdirectory on a gTLD | `acme-widgets.example/de/` | Easy to set up; low maintenance (same host) | Users may not recognise the geotargeting from the URL; one server location; harder to separate sites |
| URL parameters | `acme-widgets.example/?loc=de` | — (not recommended) | Segmentation is difficult; users cannot see the geotargeting from the URL |

- Whatever the option, each language or locale version has **its own URL**; Google recommends this over cookies or browser settings that change the language on the same URL. [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites) · [G OH 2023-01](https://developers.google.com/search/help/office-hours/2023/january)
- Localized words and Internationalized Domain Names (IDN) in URLs are fine; use UTF-8 and escape URLs correctly in links. A URL in a different language from the page content has no negative SEO effect (users may still care when they share it). [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites) · [G OH 2022-11](https://developers.google.com/search/help/office-hours/2022/november)

### How Google determines language and locale
- **Language** is detected from the **visible content** of the page: Google does not use `lang` attributes or the URL to detect it [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites); the hreflang page adds, verbatim, "Google doesn't use `hreflang` or the HTML `lang` attribute to detect the language of a page; instead, we use algorithms to determine the language" [G](https://developers.google.com/search/docs/specialty/international/localized-versions). Keep **one language per page** for content and navigation and avoid side-by-side translations. [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)
- **Target country** signals listed by Google: ccTLDs (strong); `hreflang` (tags, headers or sitemaps); server location (a signal, but not definitive with CDNs); other signals such as local addresses and phone numbers, local language and currency, links from local sites, Business Profile data where available. [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)
- gTLDs (`.com`, `.org`, …) and generic regional domains (`.eu`, `.asia`) are not tied to a location. Some ccTLDs are treated as generic: `.ad`, `.ai`, `.as`, `.bz`, `.cc`, `.cd`, `.co`, `.dj`, `.fm`, `.io`, `.la`, `.me`, `.ms`, `.nu`, `.sc`, `.sr`, `.su`, `.tv`, `.tk`, `.ws` (Google says the list may change). A gTLD site that targets one country must declare it with the page-level methods (locale-specific URLs, hreflang). [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)
- Google **ignores** locational meta tags (`geo.position`, `distribution`) and geotargeting HTML attributes, and does not vary its crawler origin to discover variations: every locale or language variant must be declared explicitly. [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)

### hreflang: methods and syntax
- Use hreflang when a page has versions for different languages or regions: fully translated pages, small regional variations in one language (e.g. English for US, GB and Ireland), or pages where only the template is translated. Google may find alternates without it, but explicit annotation is best. [G](https://developers.google.com/search/docs/specialty/international/localized-versions)
- **Three equivalent methods**: `<link rel="alternate" hreflang="…" href="…">` in the `<head>`; an HTTP `Link:` header (useful for PDFs and other non-HTML files; each URL in `<` `>` with `rel="alternate"` and `hreflang`); an XML sitemap with `<xhtml:link>` children (namespace `xmlns:xhtml="http://www.w3.org/1999/xhtml"`, children do not count toward the sitemap URL limit, the sitemap may list only URLs under its own directory). "While you can use all three methods at the same time, there's no benefit in Search"; Google adds that three implementations are much harder to manage than one. [G](https://developers.google.com/search/docs/specialty/international/localized-versions)
- Requirements for every method: each version lists **itself and all other versions** (the same set on every version); URLs are **fully qualified** with protocol; alternates may be on different domains; **if two pages do not both point to each other, the annotations are ignored**; do not combine `hreflang` with other attributes such as `media` in one `<link>`; check that the links really sit inside the `<head>`. [G](https://developers.google.com/search/docs/specialty/international/localized-versions)
- When a cluster has some broken annotations, Google keeps the ones it could validate and ignores the broken ones, with no other negative effect on the site; a `noindex` URL is excluded from the cluster. [G OH 2022-11](https://developers.google.com/search/help/office-hours/2022/november) · [G OH 2023-01](https://developers.google.com/search/help/office-hours/2023/january)
- **`x-default`**: the fallback when no listed language/region matches the user's browser setting; designed for language selectors and auto-redirecting home pages; Google says to "consider" it (it is not mandatory). Which page it points to is the site owner's choice and may differ per set of pages. [G](https://developers.google.com/search/docs/specialty/international/localized-versions) · [G OH 2022-11](https://developers.google.com/search/help/office-hours/2022/november)
- Several regional variants of one language: also provide a **catch-all** URL for users of that language in unspecified regions (e.g. a generic `en` page besides `en-US`, `en-GB`). Newly added language pages must link bidirectionally with the originating/dominant language version. [G](https://developers.google.com/search/docs/specialty/international/localized-versions)
- Sites in many countries that the team does not control directly can manage all hreflang from one place with sitemaps (cross-submission, see sitemaps.org); hreflang sitemaps are ordinary sitemaps and can live anywhere within verified sites. [G OH 2022-11](https://developers.google.com/search/help/office-hours/2022/november)
- hreflang is optional for discovery: what makes language versions findable is distinct URLs plus internal links between them. [G OH 2023-01](https://developers.google.com/search/help/office-hours/2023/january)

### Language and region codes
- Format: **ISO 639-1** language code, optionally followed by an **ISO 3166-1 Alpha 2** region code (`de`, `de-CH`, `en-GB`). Codes are case-insensitive. A language-only code is valid; a **region-only code is not** (`be` is Belarusian, not Belgium). Script variants: `zh-Hant`, `zh-Hans`, optionally with a region (`zh-Hans-US`). [G](https://developers.google.com/search/docs/specialty/international/localized-versions)
- Not supported: codes outside these standards such as `es-419`; reserved codes `EU`, `UN` and `UK` "don't have an effect" (the United Kingdom is `GB`). [G](https://developers.google.com/search/docs/specialty/international/localized-versions)
- Common mistakes per Google: missing return links, wrong language codes (including region-only), wrong or reserved region codes. Underscore forms such as `en_US` are not in the documented format *(inference)*. [G](https://developers.google.com/search/docs/specialty/international/localized-versions)

### Canonicals, duplicates and same-language regions
- Localized versions are duplicates **only if the main content stays untranslated**; translating only the boilerplate around single-language content (typical of user-generated content) can create a bad experience when the same content appears several times in results. Localized content is not penalized as duplicate content. [G](https://developers.google.com/search/docs/specialty/international/localized-versions) · [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites) · [G OH 2024-06](https://developers.google.com/search/help/office-hours/2024/june)
- With hreflang, **specify a canonical page in the same language** (or the best substitute language if none exists). `rel="canonical"` annotations carrying `hreflang`, `lang`, `media` or `type` are not used for canonicalization; alternates go in `rel="alternate"`. [G](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)
- Google prefers URLs that are part of reciprocal hreflang clusters as canonicals: if `/de-de/` and `/de-ch/` reference each other but not `/de-at/`, the first two are preferred over `/de-at/`. Never list HTTP URLs in hreflang or sitemaps instead of HTTPS ones. [G](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)
- Same language on several regional URLs (e.g. `acme-widgets.de/` and `acme-widgets.example/de/`): choose a preferred version and use `rel="canonical"` and hreflang. Regional subdomains or folders do not make identical content unique; near-identical country pages can be treated as duplicates, which can show the wrong currency in rich results; make them differ where they really differ (prices, currency, shipping) or use Merchant Center feeds for pricing. [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites) · [G OH 2024-08](https://developers.google.com/search/help/office-hours/2024/august)

### Locale-adaptive pages and redirects
- Locale-adaptive pages change content by the visitor's apparent country or preferred language on the same URL. Google "might not crawl, index, or rank all your content for different locales": default Googlebot IPs appear to be in the US and Googlebot **does not send `Accept-Language`**. Googlebot also crawls from some non-US IPs, with the same user agent string; such crawls can be verified with reverse DNS. Google recommends **separate locale URLs** annotated with hreflang. [G](https://developers.google.com/search/docs/specialty/international/locale-adaptive-pages)
- Apply robots rules (robots.txt, robots meta) **identically in every locale**. A site that blocks some countries must treat Googlebot like a user from the country it appears to come from. [G](https://developers.google.com/search/docs/specialty/international/locale-adaptive-pages)
- **Do not redirect automatically** by guessed language, and do not use IP analysis to adapt content: it is unreliable and may hide variants from users and crawlers. Offer links or a banner that lets users choose their version. [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites) · [G OH 2024-08](https://developers.google.com/search/help/office-hours/2024/august)
- If a home page does redirect (e.g. a country selector at `/`), that is the case Google names for `x-default`. [G](https://developers.google.com/search/docs/specialty/international/localized-versions)

### Language selector and internal links
- Show language and region selectors on all pages, as hyperlinks. Cross-linking language versions helps localized pages get indexed; ideally each version links to all the others. "Without internal links to those pages, Google might not know that they exist." [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites) · [G OH 2023-01](https://developers.google.com/search/help/office-hours/2023/january) · [G OH 2024-08](https://developers.google.com/search/help/office-hours/2024/august)
- Linking each selector entry to the equivalent page (not the other language's home page) is *(inference)* from "each version links to all the others".

### Translated content quality
- Scaled content abuse includes generating many pages "through automated transformations like synonymizing, translating, or other obfuscation techniques" where little value is provided to users; it is a spam policy whatever tool produced the content. [G](https://developers.google.com/search/docs/essentials/spam-policies)
- Generative AI guidance: manually fact-check and review AI output before publishing, metadata included; there is no translation-specific rule on that page. [G](https://developers.google.com/search/docs/fundamentals/using-gen-ai-content)
- Office Hours: there is **no special markup** to label automatic translations; judge translated pages by your own quality bar, `noindex` them if they are not good enough; low-quality auto-translation may hurt; have a native speaker review (and fix) translations; "a good localization is much more than just a translation of words and sentences". [G OH 2024-06](https://developers.google.com/search/help/office-hours/2024/june)
- The official documentation does not define a quality threshold for machine translation; the operational line (reviewed by a native speaker, or excluded from the index) comes from Office Hours, not from a policy page.

### Search Console per market
- The **geotargeting (International Targeting) setting no longer exists** in Search Console; there is nothing to set there. [G OH 2024-08](https://developers.google.com/search/help/office-hours/2024/august)
- A **Domain property** aggregates all subdomains, protocols and paths; a **URL-prefix property** can be a subpath (e.g. `https://acme-widgets.example/de/`), which gives per-market data for subdirectory and subdomain structures. [G](https://support.google.com/webmasters/answer/34592)
- Search Console reports mainly canonical URLs, so for same-language regional variants the clicks of a swapped URL can appear under the canonical one *(inference from canonical clustering)*.

### International structured data
- Google's feature documentation does not use `inLanguage` or `areaServed` for international targeting (not mentioned in Organization; `inLanguage` appears only in specific types such as Book). Adding them is valid schema.org and harmless, but no Google effect is documented *(inference)*. [G](https://developers.google.com/search/docs/appearance/structured-data/organization)
- Documented international properties: `priceCurrency` in ISO 4217 (required when `price` is given); **"When offering products for sale in multiple currencies, have a distinct URL per currency"**; `shippingDestination.addressCountry` and `MerchantReturnPolicy.applicableCountry` in ISO 3166-1 alpha-2 (shipping regions supported only for a restricted set of countries); Merchant Center settings take precedence over markup for shipping and returns. Organization `address.addressCountry` uses ISO 3166-1 alpha-2, and multiple addresses are allowed for several countries. [G](https://developers.google.com/search/docs/appearance/structured-data/merchant-listing) · [G](https://developers.google.com/search/docs/appearance/structured-data/organization)
- Structured data text (names, descriptions) belongs in the language of the page it describes *(inference: markup must describe the visible content)*. Validation and code formats: see SD-24, SD-26.

### Translated results in Search
- Google may translate the title link and snippet of a result into the searcher's language (21 target languages); this needs no opt-in and applies across all pages. Opt-out: `notranslate` rule in robots meta or `X-Robots-Tag`. The page does not say how this interacts with a site's own localized versions. [G](https://developers.google.com/search/docs/appearance/translated-results)

## Build rules
1. Pick **one URL structure** for all locales (ccTLD, subdomain or subdirectory) before launch; never parameters or cookies alone. → IN-21, IN-22, IN-02
2. Generate **hreflang at build time from one locale map** (page × language → URL) so every page emits the same full set, absolute HTTPS URLs and valid codes; add `x-default` for the selector or generic page. → IN-01, IN-04, IN-06, IN-08
3. Emit hreflang by **one method** (HTML `<link>` in the server-rendered `<head>`, or the sitemap for large or multi-domain setups); if two methods exist, generate both from the same map. → IN-10, IN-11
4. **Self-referencing canonical per locale**, in the same language; never canonical to the default language. → IN-07
5. **No automatic redirects** by IP or `Accept-Language` and no content swapped on the same URL; suggest the local version with a dismissible banner. → IN-03, IN-15
6. **Selector with real links** to the equivalent page, present in every template. → IN-16, IN-02
7. Translate **main content, titles, descriptions, alt text and structured data text**; have a native speaker review machine translation, or keep the locale `noindex` until it is reviewed. → IN-13, IN-17, IN-14
8. **Same robots rules** in every locale; staging rules not carried into one locale. → IN-20
9. Ecommerce: one URL per currency/market, structured data codes per market. → IN-18, IN-19
10. At launch, add a URL-prefix property per locale in Search Console. → IN-23

## Notes by site type
- **ecommerce**: currency, prices, shipping and returns per market are the real differences between same-language country pages (e.g. Acme Widgets on `acme-widgets.example/en-us/` and `/en-gb/`); show them in the visible text and in markup, one URL per currency. Merchant Center settings take precedence over markup for shipping and returns, and Google suggested Merchant Center feeds against wrong-currency rich results; one feed or feed target per country is *(inference)* from that. → IN-09, IN-18, IN-19 [G](https://developers.google.com/search/docs/appearance/structured-data/merchant-listing) · [G OH 2024-08](https://developers.google.com/search/help/office-hours/2024/august)
- **editorial**: translate articles fully (not only the template around them) and link each translation to the original with hreflang; keep the same author byline on each translation and name the translator where readers expect it *(inference)*. Do not publish unreviewed machine translations at scale. → IN-13, IN-14, IN-01
- **local-business**: bilingual regions (e.g. Northwind Physio in Oslo with `nb` and `en` pages) use one URL per language with the same name, address and phone; the target country comes from local address, phone and Business Profile, not from geo meta tags. → IN-02, IN-12 [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)
- **personal-brand**: a two-language portfolio (e.g. Ada Novak, `en` and `sl`) needs distinct URLs, reciprocal hreflang and one identity in both languages (see `entity-personal-brand.md`); `x-default` is optional without a selector page. → IN-01, IN-08
- **professional-services**: an Italian firm with an English section (e.g. Studio Ferri Orientamento, `/it/` and `/en/`) translates the service pages that matter to foreign clients rather than the whole site; untranslated pages simply have no alternate in the cluster. → IN-01, IN-13
- **saas-product**: documentation per language under its own path (`/docs/de/…`) with hreflang to the source page; a partially translated docs set links missing pages to the dominant language, not to a 404; no language switch done only client-side. → IN-01, IN-06, IN-15 · RJ-31

## Myths and outdated advice
- ⚠ "Set the target country in Search Console" → the geotargeting setting no longer exists. [G OH 2024-08](https://developers.google.com/search/help/office-hours/2024/august)
- ⚠ "`lang`, hreflang or geo meta tags (`geo.position`, `distribution`) tell Google the language or country" → language is detected from visible content (`lang` and URL not used per the multi-regional page; hreflang and `lang` not used per the hreflang page); geo meta tags are ignored. See `myths-deprecated.md`. [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites) · [G](https://developers.google.com/search/docs/specialty/international/localized-versions)
- ⚠ "Redirect visitors automatically by IP or browser language" → do not; use URLs per locale and a selector. [G](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)
- ⚠ "`en-UK`, `EU`, `es-419` are valid hreflang codes" → not supported; use `en-GB`, a language-only code or one code per country. [G](https://developers.google.com/search/docs/specialty/international/localized-versions)
- "Translated pages are duplicate content and get penalized" → no; they are duplicates only when the main content is untranslated. [G OH 2024-06](https://developers.google.com/search/help/office-hours/2024/june)
- "Use hreflang in HTML and in the sitemap to be safe" → the methods are equivalent; using all three at once gives no benefit and is harder to manage (Google); two methods that disagree create a conflict *(inference)*. [G](https://developers.google.com/search/docs/specialty/international/localized-versions)
- "Label machine translations with special markup" → there is none; review them or `noindex` them. [G OH 2024-06](https://developers.google.com/search/help/office-hours/2024/june)
- "One broken hreflang link ruins the whole site" → Google ignores the broken annotation and keeps the valid ones. [G OH 2022-11](https://developers.google.com/search/help/office-hours/2022/november)
